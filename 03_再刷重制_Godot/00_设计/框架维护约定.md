# 框架维护约定

【Codex·未经Claude检验】｜双入口已建立；游戏系统为待实现目标｜2026-10-12

## 目标与范围

以当前正式 Mac 西游改版为本期重制来源，本轮确认 v0.04。共用启动界面提供「西游改版」与「新版」两入口；先重制当前西游，新版尚未设计，只保留未开放入口。Steam 原版审计不作为当前前置条件，也不用于替换西游规则。

当前仅实现入口路由与保存位置计算。西游开发预览尚无玩法，新版没有内容场景。共用基础设施与各模式内容分开。

## 内容与运行逻辑

- 角色、技能、装备、状态、掉落、养成和副本使用统一结构及稳定 ID。显示名称不作为唯一标识。
- 当前西游来源 ID 与 Godot ID 通过映射连接，保留正式版来源及文件指纹。转换时核对插件备注、运行模块和真实行为，不能仅复制数据库便宣称机制已迁移。
- 普通新增内容通过数据与模板接入。新机制在独立效果模块实现，定义输入、作用时点、目标、消耗与结果。
- 战斗规则、界面表现、平台输入与数据读写分开维护。界面读取已计算结果，动画不直接决定伤害或掉落。
- 共用效果明确结算顺序、追击上下文、费用、重复触发与随机结果记录；验收按规则例子验证行为，不仅检查能否启动。
- 效果参数与公式作为统一来源，帮助文字从同一数据生成可生成的部分，特殊说明明确登记并核对。文本写法保持准确、清楚，特殊前提、施放条件、费用与当前成长值不能被一律隐藏。

## 角色接入的预期流程

1. 填写角色、成长、技能、获取方式与必要条件。
2. 提供头像、地图角色、战斗动作及素材来源记录。
3. 配置已有效果模块；新机制另增加模块和对应验证例子。
4. 检查 ID、引用、缺失素材、费用、说明与效果参数。
5. 验证战斗、队伍、图鉴、获取、保存读取；合并前看实际画面。

角色模板与填写工具属于待实现功能。第二批角色能否通过该流程接入，是扩大重制范围的判断依据。

## 保存与平台

- 使用独立应用标识、独立保存目录和带版本号的保存结构。
- 开发保存位置使用 `KYO/再刷重制_开发`，模式内分 `modes/xiyou` 与 `modes/new`。本轮不读写保存或导入玩家真实进度，新版暂不创建玩法/保存内容。
- 开发与验收使用隔离新档或明确提供的副本，不触真实玩家进度。
- 不迁移 MV 旧存档（用户 2026-10-12 明确）。跨平台存档导入/导出只针对 Godot 版自身存档。
- 当前只做 Mac 版（用户 2026-10-12）；Windows、Android 等 Mac 版完成后再启动。届时各平台共用内容与规则，输入、界面、资源策略和发布配置分别维护。
- 同时记录打包结果、虚拟机运行与真实设备验收，不能互相替代。

## 后续工程布局建议

在唯一 Godot 工程内按职责组织 `core`（通用基础）、`systems`（战斗/装备/保存等）、`content`（角色等数据）、`scenes`（场景和界面）、`assets`（实际使用素材）、`platform`（平台适配）及 `tests`（规则验证）。这是建议，创建实际工程时再固定详细路径，避免提前建立大量空模块。

每个系统保留一个权威实现。新增内容优先复用明确接口，避免在多个无关脚本中重复修补。核心接口或数据结构变更时，同轮更新依赖检查、迁移说明和验收记录。
