# 框架维护约定

双入口与首期玩法已实现；完整系统与角色工具仍待接入｜2026-10-12

## 目标与范围

以当前正式 Mac 西游改版为本期重制来源，实际版本与转换范围见来源登记。共用启动界面提供「西游改版」与「新版」两入口；先重制当前西游，新版尚未设计，只保留未开放入口。Steam 原版审计不作为当前前置条件，也不用于替换西游规则。

当前已实现入口路由、原版开局事件（选存档位/难度/英雄/教派）、首层地图/事件/战斗/商店、状态/装备、Godot 独立保存与基础界面。装备第二期已接入品质、随机词缀、强化槽、套装与符文之语；完整楼层、其余养成和特殊角色机制仍是目标；新版没有内容场景。共用基础设施与各模式内容分开。

## 内容与运行逻辑

- 角色、技能、装备、状态、掉落、养成和副本使用统一结构及稳定 ID。显示名称不作为唯一标识。
- 当前西游来源 ID 与 Godot ID 通过映射连接，保留正式版来源及文件指纹。转换时核对插件备注、运行模块和真实行为，不能仅复制数据库便宣称机制已迁移。
- 普通新增内容通过数据与模板接入。新机制在独立效果模块实现，定义输入、作用时点、目标、消耗与结果。
- 战斗规则、界面表现、平台输入与数据读写分开维护。界面读取已计算结果，动画不直接决定伤害或掉落。
- 共用效果明确结算顺序、追击上下文、费用、重复触发与随机结果记录；验收按规则例子验证行为，不仅检查能否启动。
- 效果参数与公式作为统一来源，帮助文字从同一数据生成可生成的部分，特殊说明明确登记并核对。文本写法保持准确、清楚，特殊前提、施放条件、费用与当前成长值不能被一律隐藏。

## 角色接入的预期流程

1. 填写角色、成长、技能、获取方式与必要条件。
2. 提供头像、地图角色、战斗动作及素材来源记录。
3. 配置已有效果模块；新机制另增加模块和对应验证例子。
4. 检查 ID、引用、缺失素材、费用、说明与效果参数。
5. 验证战斗、队伍、图鉴、获取、保存读取；合并前看实际画面。

角色模板与填写工具属于待实现功能。第二批角色能否通过该流程接入，是扩大重制范围的判断依据。

## 保存与平台

- 使用独立应用标识、独立保存目录和带版本号的保存结构。
- 开发保存位置使用 `KYO/再刷重制_开发`，模式内分 `modes/xiyou` 与 `modes/new`。本轮不读写保存或导入玩家真实进度，新版暂不创建玩法/保存内容。
- 开发与验收使用隔离新档或明确提供的副本，不触真实玩家进度。
- 不迁移 MV 旧存档（用户 2026-10-12 明确）。跨平台存档导入/导出只针对 Godot 版自身存档。
- 当前只做 Mac 版（用户 2026-10-12）；Windows、Android 等 Mac 版完成后再启动。届时各平台共用内容与规则，输入、界面、资源策略和发布配置分别维护。
- 同时记录打包结果、虚拟机运行与真实设备验收，不能互相替代。

## 后续工程布局建议

在唯一 Godot 工程内按职责组织 `core`（通用基础）、`systems`（战斗/装备/保存等）、`content`（角色等数据）、`scenes`（场景和界面）、`assets`（实际使用素材）、`platform`（平台适配）及 `tests`（规则验证）。这是建议，创建实际工程时再固定详细路径，避免提前建立大量空模块。

每个系统保留一个权威实现。新增内容优先复用明确接口，避免在多个无关脚本中重复修补。核心接口或数据结构变更时，同轮更新依赖检查、迁移说明和验收记录。

## 装备实例与规则接口（已实现）

- `XGear` 按正式 DreamX/YEP 顺序生成实例：前后缀合并、备注参数覆盖、属性浮动、插槽浮动。品质只决定名称/颜色（七档名称、颜色、说明卡边框与标签统一在 `XQuality`；`XGear.quality` 仍返回旧 0～15 档供排序）；不自行添加品质倍率。随机数来源见下一条（不导入 MV 存档里的池，新游戏自己生成）。
- `XGearUpgrade` 在副本计算、检查所有条件后，才消费材料并修改同一实例；预览不消耗随机数。实际随机强化保留正式插件的范围（未带正负号的 Random N 为 -N 至 N+1）。
- 装备随机数照 Star_RomGetItems：词缀掷骰/选取与属性浮动从存档里的「预掷随机池」按序号取（20 个，序号超过 15 时整组重掷），所以读档后再获得同一件装备结果不变；插槽浮动与强化随机值是现掷。正式版属性浮动可越过池末尾得到 NaN，Godot 越界时改为现掷（有意修正）。对照：`equipment_probe.cjs` 的变化随机序列，名称/属性/插槽与取随机数次数都一致。
- 出战 5 人（MrTS_BattleCharacterLimit 覆盖 YEP_PartySystem 的 4）；编队界面未做，按队伍前 5 人。战斗经验按 MV 发给全队，阵亡与后备也得（后备系数取 System「后备成员获得经验」），满级不再获得。
- `XEquipSuits` 根据当前装备动态累加达成的档位：属性、倍率、附加技能/状态/免疫、全队经验/金钱/掉率。解除装备立即撤销，不把套装状态永久写入角色。
- `XRunewords` 对照正式 v0.05 的运行模块：最近镶入序列末尾匹配，最长配方优先，每件最多一条；同名数值备注相加，已形成的属性与名称随实例保存。
- 存档结构版本 2：每件装备有稳定 `instanceId`，保存词缀、属性、插槽、强化序列与符文之语。Godot 版 v1 补充实例标识和规则字段，保留已有属性；不重抽，也不导入 MV 档。
- 正式版 4 个旧 `<Upgrade Effect>` 材料没有生效效果，转换器记录问题；Godot 不开放只扣材料/插槽的空操作。填孔器允许在 12 孔装备上使用（原版把打孔/填孔同标为 addSlots，错误拦截上限）。
- 本期只接入通用装备规则。法宝成长/唤醒、宝珠装卸、制作、角色专属机制及未翻译技能/状态脚本按后续内容批次实现；数据库字段的导入不代表这些系统已完成。

## 地图事件与开局（已实现）

- 新游戏照 MV setupNewGame：空队伍、难度为 Vitsuno 初始值、站在 System 起点 Map001，之后完全由原版事件推进：Map001 选固定存档位/名字/难度 → Map002 剧情与选英雄 → Map221 选教派 → 方桌大厅 EV20（首次到达存档、按难度学被动、开局可选角色学 2571/2786）。不再有 Godot 自制的选难度/选英雄窗口。
- 地图上放哪些事件由切片配置 `keepEvents` 决定：`"*"` 为整张图（开局三张图），否则列出事件 ID。转换器照样扫描整张图的引用（素材、敌群、公共事件、事件入队的角色、地图动画、移动路线的音效/换图）。
- 自动执行事件照 MV：解释器空闲时每帧找第一个满足条件、指令多于一条的自动执行事件运行；场所移动后旧事件剩下的指令在新地图上继续执行，按事件 ID 找角色/提示位置时找的是新地图上同 ID 的事件（与原版相同，例如「伙伴号角」提示浮在 Map221 的 2 号雕像处）。
- `MVInterpreter` 已支持：文字/选项/数值输入（YEP_X_ExtMesPack1 连续选项合并，直接改指令列表）、条件分支、循环与跳出、标签与跳转、公共事件、开关/变量/独立开关、金钱/物品/装备（MOG_TreasurePopup 获得提示）、队员、增减技能（318）、场所移动、移动路线（含等待）、透明、动画、气泡、淡入淡出、等待、BGM/SE、战斗、商店、全回复、回标题、脚本（355/655）、插件指令（356：Difficulty SetID、GhostButtons、ProhibitHangUp）。未支持的指令记进 skipped 并在日志列出。
- 脚本不执行 JavaScript：`MVScript` 只认正式版里出现过的写法并按语义翻译（所有角色学/忘技能的几种循环、固定存档位存档的成功/失败分支、prompt 输入名字、toaster 提示、按变量取物品、DCultyL 标记、RomGet 预掷池初始化等）；认不出的语句原样记进 skipped。新内容遇到新写法时在这里补翻译并加 `tests/xiyou_script` 例子。
- 「所有角色学会/忘记技能」：MV 会当场建出全部角色；Godot 角色按需建，所以把这类操作按顺序记在 `XState.actor_ops`（随存档），角色第一次建出时依次补上，已建的角色立即生效。效果与原版相同，只是不预先建出几百个角色。
- 固定存档位：开关 161～165、276～280 对应 1～10 号（`XState.fixed_save_slot`），事件脚本里的 `DataManager.saveGame($gamePlayer.SaveGameId)` 翻译为 `XSave.save(该格)`；`XSave` 共 30 格：开局仍只选 1～10，地图备份依次写到 11～30 的首个空格，不覆盖已有备份。备份会更新最近存/读格，一键存档之后也存到该格（照正式 v0.10 跟踪规则）。主菜单「存档」照 YEP_MainMenuManager 预约公共事件 1，关菜单后由地图执行（`XMapScene.run_common_event`，事件 ID 为 0）。「一键存档」照 installV010UsabilityRuntime 存到 `XSave.current_slot`（最近一次成功存档/读档的格；新游戏为 0，此时打开选格存档页）。
- 开战状态标签（dsPassiveSkill Scene_Battle.start）：每个出战角色依次处理装备与技能上的 StartPushState（自己）、StartRomActPushState（随机队友）、StartRomEmePushState（随机敌人）、StartRomPushState（随机任一目标）、StartAEPushState（全体敌人）、StartWTPushState（全队），之后刷新双方被动缓存（`XBattleLogic._battle_start_states`）。对照基准覆盖全部六档难度；探针加完开战状态后补一次 refresh（krz_state_re 的状态缓存要下一次 refresh 才更新）。

- 连击计数（dev.018）：`battle/combo_counter.gd`（`XComboCounter`）是战斗场景的子节点（随胜利镜头缩放，同 MV Spriteset 子精灵）。`XBattleScene._play` 在每个行动开始/收尾调 `action_started/ended`（BattleManager.startAction/endAction），`_show_hit` 显示伤害时调 `applied`（Game_Action.apply＋executeDamage 的计数规则）；逐帧逻辑在 `step()`（物理帧），测试可直接调用。

## 难度提示（dev.019，已实现）

- `core/difficulty_notice.gd` 是西游模式内延迟启动的跨场景计时节点，`map/difficulty_notice.gd` 画地图提示；不把绘制规则或计时写入存档，不依赖共用 GameApp。原版默认 2，难度变化才弹出（简单 2→2 不弹），60ms 读颜色、30ms 倒数、32ms 绘制，按墙钟计时，不跟游戏加速。
- 开战不重新触发：原版 `_tipSpr` 只在 Scene_Map，战斗看到的文字来自地图快照；Godot `_snapshot` 保留该提示，开战后隐藏活节点、后台继续倒数，回地图时按剩余时间恢复。原版 Sprite 的文本中心在画面中线左 25 像素，沿用。
- 品质单一来源：转换器 v7 从运行模块解析名称/颜色/边框/标签及旧档映射到 `UnifiedQuality.json`；`XQuality` 是全部消费者入口，去掉手写常量与说明卡第二套参数解释。
- 命中（dev.022）：`XBattleLogic.item_hit/item_eva` 照正式链——dsPassiveSkill 必中被动为 1，否则 YEP_HitAccuracy 的「Accuracy Formula」（西游：skillHitRate × (userHitRate − targetEvadeRate) × 1.2；物理用 hit/eva，魔法用 hit×1.1/mev，必中 10000000/0），闪避公式为 0，最后夹到 0～1。公式字符串取插件参数用 Expression 求值；实战 `apply` 与智能AI共用。此前 Godot 用 MV 原生（命中×hit、另掷闪避），属于未移植。
- YEP 行动序列：转换器 v9 给技能/物品加 `yepEffects`（whole＋target 序列里 ACTION EFFECT 的条数；默认序列含 max(1, repeats) 条，YEP 之后 repeats 被改成 1；if 行被存成整行，条件不生效）。目前只供智能AI估算段数；实战多段仍按数据库 repeats，是否改成按序列段数待战斗画面对照时一并核对。
