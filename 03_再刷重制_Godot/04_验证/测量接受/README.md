# 测量接受单

`同步正式西游.py --accept-changes <接受单.json>` 用的接受单放这里并提交，作为接受既有参照测量改变的永久记录。规则见 [长任务与增量同步](../../07_开发环境/长任务与增量同步.md)。

- 文件名：分支名把 `/` 换成 `_`，如 `claude_某任务.json`；同一分支多次接受就在同一文件追加条目，或另起 `<分支>_2.json`。
- 条目从拒收那轮同步报告（`04_验证/本地结果/自动同步/<时间>/同步报告.json`）的 `changeCandidates` 复制，人工核过每条变化后补 `reason`（至少 4 个字，写清为什么这次变化是对的）。
  可用 `python3 03_再刷重制_Godot/03_转换工具/生成接受单.py --out <本目录>/<分支>.json [--reason 理由 | --reason-from <交付单>]` 照抄成草稿（默认取最新一份报告；已有文件只追加没有的条目），核过再提交。合并时被拒就用 `合并车道.sh <任务> --accept-changes <接受单>` 接着同步。
- 每条必须恰好用上：对不上本轮变化（摘要不同、字段不同、本轮没有这条变化）就整轮拒收，所以旧接受单不能放行之后的新变化。
- `合并车道.py` 合并时自动把车道带进来的接受单传给 main 的同步。

```json
{
  "schema": 1,
  "accept": [
    {
      "file": "events.json",
      "collection": "cases",
      "key": "[[\"id\",\"示例\"]]",
      "fields": ["value"],
      "oldDigest": "0123456789abcdef",
      "newDigest": "fedcba9876543210",
      "reason": "探针改读运行时实际值，原记录取的是默认值"
    }
  ]
}
```
