# 发布

后续记录内容版本、Godot 与模板版本、平台适用范围、保存兼容、逐文件校验和回退方式。发行说明按玩家偏好简述更新方向，必要安装与迁移操作准确保留。

导出结果放 `导出包/`，不进入 Git。签名凭据单独保存，不写进资料、日志或公开包。旧西游 MOD 的编号登记本轮保持；新项目编号方案在首个运行候选前明确。

导出预设两个：「macOS 验收」是调试包，保留 `tests/`（`--verify-export` 在包内跑 `tests/xiyou_mac_export.tscn`）；「macOS 发行」是给玩家的包，另外整个排除 `tests/`。两个都排除不进游戏的参照数据（`generated/oracle`、`manifest.json`、`sync_stamp.json`）和 `builds/`。`检查.sh` 的「导出包排除测试与参照数据」检查这些排除项，并确认游戏数据没被误排除。

导出冒烟（2026-11-05 mac1）：`python3 07_开发环境/导出冒烟.py` 一条命令导出「macOS 验收」、解包、只读查签名与架构，在隔离临时 HOME 里无头跑包内 `xiyou_mac_export`（字体、资源、存档写读）和 `xiyou_flow`（入口→新游戏→进一层→自动战斗→存读档），报告写到 `04_验证/本地结果/导出冒烟/<时间>/报告.md`；`--keep` 留下 .app 给实机验收。调试包里用 `-- --verify-export --verify-scene=<tests 下的 xiyou_ 场景名>` 换跑别的场景。要 Kyo 本人做的（听音、Intel、签名公证）见 `00_项目管理/Mac实机验收清单.md`。不签名、不公证、不上传。

更新清单（2026-11-11 pro-update-manifest）：`python3 07_开发环境/生成更新清单.py --old <旧版本目录> --new <新版本目录> --key <仓库外私钥> --out <目录>` 比较两个版本目录，写逐文件的补丁清单（路径、字节数、SHA-256、删掉的文件、版本号、底包号、最低基线）并签名，见[更新清单生成说明](更新清单生成说明.md)。玩家客户端读的 `channel.json` 仍由 `发布补丁.py` 写；`发布补丁.py --old-tree <底包工程目录>` 会顺带调它，`--stage` 时清单随补丁进发版仓库。

强制更新（2026-11-14 cc/force-update，Kyo 定）：`channel.json` 可带两项，老客户端读到不出错、新客户端读不到就不强制——
- `min_playable`：最低可玩的开发编号。玩家正在运行的号低于它（且清单真有更新的版本），进标题前盖一层关不掉的更新框：有不低于它的补丁就「更新」（失败可以一直「再试一次」，旁边给手动下载）；底包太旧、或这个底包的补丁还不够新，只给「打开下载页」和「重新检查」。出标题时最多等 8 秒（`XForceUpdate.DEFAULT_WAIT_SEC`）。连不上更新服务器、清单坏、验签不过一律放行，标题左上角提示「未能检查更新」。
- `download_url`：手动下载页（只认 https）；客户端只认清单里的值，不写死地址；没有就只写「请到 QQ 群…的群文件下载」。QQ 群文字一直留作补充说明。
- 用 `发布补丁.py` 设：`--min-playable <号>`（`latest`＝本次发布的号，所有旧版都强制；`0`＝取消），`--download-url <https 地址>`（`none`＝去掉）。不给就沿用清单原值，默认不改；设了 `min_playable` 却没有下载页（参数没给、清单里也没有）时，自动填 Gitee 发行版页面 `https://gitee.com/kyoluu/play-again_-xiyou_-kyo/releases`（Kyo 11-14 定，`DEFAULT_DOWNLOAD_URL`），强制同时给 `none` 会被拒；`--min-playable` 不能比本次发布的号大（否则装到最新也进不去）。小修小补别调它，照旧走红点。
- 只有装了这段逻辑的客户端认 `min_playable`；更早的客户端（含 v0.01.09 及以前）照旧只看红点。客户端回退开关 `XForceUpdate.ENABLED = false`。

资源加密（2026-11-24 T452，Kyo 定「只做2」：只加密发行包，公开仓照旧公开）：三个「发行」预设开 Godot 资源包加密（AES-256；脚本、json、场景、资源、cfg、remap 进加密范围；只加密文件、不加密目录，包内文件名单照旧能审计），验收预设不动。
- 密钥：私密设计仓 `发行密钥/pck_encryption_key.json`（和存档封存密钥同一处，随私密仓推送备份；换电脑 `git pull` 私密仓即可）；GitHub 仓库 Secret `GODOT_SCRIPT_ENCRYPTION_KEY` 另存一份，只给编模板的工作流用。公开仓的预设、脚本、工作流、文档里都没有密钥，导出时由 `资源加密.py` 放进环境变量。
- 模板：要用同一把密钥编的导出模板。`python3 07_开发环境/资源加密.py templates` 在 GitHub Actions 上编（工作流 `.github/workflows/encrypted-templates.yml`，约 1～2 小时），前台等完、下载解密、装到主工作区 `07_开发环境/导出模板/4.7.2.stable_aes/`，模板 SHA256 记回私密仓的密钥文件。日常改脚本、json、图不用重编；只有换密钥或升级 Godot 才重编。`资源加密.py status` 查密钥和模板对不对得上。
- 出包与补丁：`发行出包.py`、`发布补丁.py` 自动带密钥导出；缺密钥或模板不是这把密钥编的就不出包。导完 `资源加密.py scan` 逐个查该加密的都加密了、包外没有明文。预设里的 `seed` 让同样的内容每次加密结果一样，补丁照旧三端逐字节相同、一个补丁通用。
- 旧整包：加密前的旧整包读不了加密补丁，`发布补丁.py` 不给它们出补丁（报「底包是加密前的旧整包」）；旧包玩家在游戏里看到「这个版本要换新的安装包」，去下新整包。出第一个加密整包时 `发布补丁.py --full-only --min-base <这个整包的开发编号>`（旧整包一律提示换安装包，文案是原有的「这个版本要换新的安装包，游戏内更新不了。」），要不要再加 `--min-playable` 强制换包由 Kyo 定。
- 丢了密钥：已装的游戏照常玩，存档不受影响（存档封存是另一把密钥）；但新补丁没法再给已发的整包用，只能换新密钥、重编模板、出新整包让玩家重下。私密仓那份就是备份，别删。
- 回退：`资源加密.py` 的 `ENCRYPT = False`（导出用的工程副本里关掉加密，加密模板照样能跑明文包）。
- 挡得住什么：玩家用解包工具直接打开包，只看得到文件名和密文，读不到脚本和表；密钥编在游戏程序里，有心人能从程序里把它挖出来——这档只防一键解包改表，不防专门逆向。

补丁与存档密钥（2026-11-25 T489，v0.04.01 事故后定的出包规矩）：发行存档封存密钥只在出包时注入、不进仓库；Godot 4.4 起 `--export-patch --patches <底包>` 会把「底包里有、这次工程里没有」的文件记成删除，0.04.01 因此把 `content/save_seal_key.json` 删了，玩家装上补丁后游戏退回明文模式、加密的 `.ksv` 存档在读档页全部看不见（文件本身没坏，撤回补丁就回来）。现在：
- `发布补丁.py` 底包带密钥就在导出用的工程里注入同一把（与整包同源、同样查格式），导完删。
- 补丁目录里不许有删除条目：有就拒出包，名字写在报错里；确实要删某个底包文件，单次加 `--allow-removal <路径>`，常设放行写进 `ALLOWED_REMOVALS`（都要在交付单写理由）。
- 存档门禁：导完用底包目录里的真 mac 包＋这份补丁，读发行密钥封存的 `.ksv` 档必须进得了地图（临时 HOME、无头静音，约 1～2 分钟）。`--base` 要给 `devNNN_三平台发行` 目录；不是 Mac 或目录里没 mac 包时只能 `--skip-save-gate "<理由>"`，理由写进交付单，换家核查时看。
- `补丁叠加验证.py --real-base <devNNN_三平台发行>`：同样用真底包和真 mac 包跑六次载入检查，再加一次 g（读封存存档进地图）。自己导的底包没有发行密钥，测不出这类问题；动补丁载入、存档封存、出包工具时跑这一条。
- 「读档 0 报错」不能当存档没问题的证据：缺密钥时游戏不报错，只是悄悄换成明文模式；要看读档页／读档后进没进地图。
