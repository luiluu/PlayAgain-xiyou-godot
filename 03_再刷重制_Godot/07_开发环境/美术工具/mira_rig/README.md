# 米拉黑龙骨骼拆件（T213 试做）

所有动作帧都从**同一张待机图** `01_Godot工程/content/mira/img/sv_actors/sv/UserSV_MiraDragon/UserSV_MiraDragon1_0.png` 拆件、绑骨、摆姿势后离线烘焙。不重新画头、角、鳞片，所以每一帧的形象都和待机一致。

这里只是试做：没有替换工程里的 21 张图，也没有接入战斗。离线工具放在 Godot 工程外面，不会被导出带进游戏包。

## 文件

| 文件 | 干什么 |
|---|---|
| `rig.json` | 骨骼工程：部件多边形（labels）、按颜色剥离的规则（relabel）、骨骼（bones）、图层与蒙皮（layers）、各动作的姿势（poses） |
| `bake.py` | 烘焙器：切部件 → 蒙皮 → 反解取样 → 清理 → 输出 340×280 PNG；`--parts` 导出部件图 |
| `check.py` | 自检（退出码 0 才算过）：部件拼回＝1_0、rest 烘焙＝1_0、成品尺寸、alpha、底锚、孤立点、小透明洞 |
| `board.py` | 出对比板（原稿同号帧｜新｜1_0，原尺寸）和头部 1:1 并排，各另出一张 ×3 放大图辅助看 |
| `parts/` | 部件图（`check.py` 会重新生成）：0 远侧翼、1 身体（含补画）、2 头颈链、3 近侧翼、4 前景（近侧前腿、后腿和尾巴） |
| `out/` | 烘焙成品和对比板 |

依赖 Pillow＋numpy（系统 python 一般没有：`python3 -m venv /tmp/rig-venv && /tmp/rig-venv/bin/pip install pillow numpy`）。

```sh
cd 03_再刷重制_Godot/07_开发环境/美术工具/mira_rig
python bake.py rig.json 14_0 out/UserSV_MiraDragon14_0.png   # 烘焙并打印自查数字
python board.py 14_0                                         # 对比板
python check.py                                              # 自检
```

## 原理

- **部件**：`labels` 中的多边形按顺序判定，先命中的部件优先；没有命中的不透明像素都归 `body`。`relabel` 用来把颜色在指定范围内、并且和目标部件四连通的像素改归目标部件，例如把下巴后面露出的远侧翼红膜从头颈部件剥给远侧翼。
- **补画**：图层的 `fill` 只补原图里被其它部件挡住的位置，所以 rest 姿势拼回去仍然和 1_0 逐像素一致。补的颜色按 `offsets` 从同层纹理平移复制；`rim` 在补出来的顶边描一道和原图同色的轮廓线和亮边。目前只给身体补了脖根到肩背这一块，脖子垂下以后会露出来。
- **骨骼与蒙皮**：每块骨骼有 `pivot` 和 `parent`。姿势里写 `rot`（单位为度，正值表示屏幕上顺时针）和 `offset`（像素）。蒙皮有三种：
  - `rigid`：整层跟着一根骨头动。
  - `radial`：离 `center` 越远，跟 `bone` 动得越多；在 r0～r1 之间平滑过渡到 `parent`（翼根贴着肩膀，翼面整片转）。
  - `chain`：按到关节折线的投影弧长分配权重，关节附近 ±`blend` 像素内平滑过渡（脖子分 5 节，弯起来是连续的弧线，没有断口）。
- **取样（RotSprite 同类做法）**：先把每层用 Scale2x 放大三次（8 倍），再从每个目标像素中心用牛顿迭代反解回原图坐标，取放大图上最近的像素。成品只用原图里有的颜色，alpha 只有 0 和 255，不会发糊。不动的地方取到的就是原像素，所以 rest 姿势的差异是 0。
- **清理**：删掉孤立点（八邻都透明的像素），补上烘焙中新出现的、面积不超过 4 像素的封闭透明洞（取四邻里最多的颜色）。1_0 本身就有的小洞保留。

## 摆下一个动作

1. 在 `rig.json` 的 `poses` 里加一项，例如 `"3_0": {...}`。可以用的骨头有：`n0`～`n3`（脖子，从下往上）、`head`、`farwing`、`wingN`、`body`。
2. 先只调大关节：头颈的总转角等于 n0～head 的 rot 之和，抬头用正值，低头用负值；翼往后收用正值。
3. 运行 `python bake.py rig.json 3_0 out/UserSV_MiraDragon3_0.png`，再运行 `python board.py 3_0`，以原尺寸的对比板为准。
4. 出现新的空洞或破口（某个部件挪开后露出底下的空白），就在对应图层加 `fill` 多边形，坐标是 1_0 的原图坐标。
5. 运行 `python check.py`，退出码为 0 才能交。

14_0 现在的姿势是：脖根下沉 11 像素，脖子两节各弯 −45°，头回正 +15°（头颈总共转了 −70°）；远侧翼转 40° 后平移到背后，大部分被近侧翼挡住；近侧翼往后斜 28°。

## 没用 Godot Skeleton2D 的原因

派单建议可以用 Godot 的 Skeleton2D。最后选了离线 Python，原因有三：

- 烘焙成品必须是逐像素可控的 PNG。用 Godot 渲染出来的旋转图会经过过滤和插值，要额外关掉，还要另写截帧。
- Python 可以直接断言「拼回＝1_0」，`check.py` 能并进现有的自检。
- 不需要启动 Godot，也就不涉及声音。

如果以后要在游戏里实时动起来（不是烘焙成帧），可以把 `rig.json` 的骨骼和部件图搬进 Skeleton2D，两边的数据结构是一一对应的。
