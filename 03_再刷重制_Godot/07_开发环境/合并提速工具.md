# 合并提速工具

本工具按交接板 2026-10-16 的沙僧协助计划制作。只改变开发流程，不改变游戏规则；交叉核查与人工进度估计继续由原工作者负责。

## 同步正式西游：自动识别新增用例

`python3 03_再刷重制_Godot/03_转换工具/同步正式西游.py --accept-additions`

仍先备份、转换、运行全部参照探针并核对来源。识别已知参照的稳定用例键：事件 id、敌群/交礼、伤害双方与技能、AI 场景与角色、商店商品与状态等；同键重复项按多重集逐条比较。旧用例必须全部完全相同，只允许新增键。新地图还检查通行度矩阵结构。

- 不带参数也会报告“只增新用例”，退出 2，留给人工核对；带参数且同源验证通过才自动接受并登记，退出 0。
- 只有正式版本与运行脚本完全相同、旧输入 SHA 全部原样保留才允许自动接受；新增切片输入可以增加。
- 旧用例改变/删除、同键追加、未知结构变化、新用例报错或不结束、来源校验失败，一律不自动接受。
- 来源身份只忽略顶层字段；用例中的 source 等测量内容不会被忽略。
- worktree 继续自动不登记；`--no-register` 也保持有效。完整比对在备份目录的同步报告.json 中，不只打印摘要。

## 合并车道：准备与收尾

在 main 使用工具，任务名对应现有的 `claude/<任务>` 或 `codex/<任务>` 工作树；主工作区与车道均须干净，交付单标为“可合并”。

1. `03_再刷重制_Godot/07_开发环境/合并车道.sh <任务> --dry-run`：只读计划，不建状态文件、不合并、不清理。
2. `03_再刷重制_Godot/07_开发环境/合并车道.sh <任务>`：正常 merge --no-ff；切片/转换器/参照探针有改动才同步并导入；游戏内容有改动才递增开发编号；把交付单草稿并入变更记录并替换编号占位，删除交付单。仅测试、文档与工具不递增游戏编号。
3. **唐僧手改交接板和进度账**：移除活动车道，加入待交叉核查（写车道分支或提交号），按实际范围更新完成度。改动先保留未提交。
4. `03_再刷重制_Godot/07_开发环境/合并车道.sh <任务> --finish`：核对登记、原始加权合计与预期文件范围；运行完整检查和 oracle；提交收尾，再调用既有工作树清理保护。默认执行者 Claude（唐僧）；额度接力时两步均加 `--executor Codex`。

交付后若另一个车道先合并 main，仍可正常合并；有冲突就停止保留。工具不自动解决冲突、不重置、不删除失败现场、不顺带暂存其他文件。状态在 `.git/lane-merge/state.json`，重复准备不会重复追加草稿或递增编号；失败可查看状态后接续。main 或车道 HEAD 被预期外改变时先人工核对。执行中的同类工具用互斥锁串行；若进程被强行终止留下 running.lock，确认旧进程已结束再人工移除该锁。

## 进度账：只对总和取一次小数

- `python3 03_再刷重制_Godot/07_开发环境/进度账.py`：只读，打印原始加权和与一位小数显示值。
- 加 `--check`：核对账表合计、当前状态中的数字，不一致返回非零。
- 加 `--write`：更新各行原始“计入”、合计与当前状态；不替人评估完成度。需要更新口径时显式加 `--as-of dev.NNN`，否则保留已核口径。

使用 Decimal 计算，权重必须合计 100，完成度须在 0～100。dev.057 的原始值 22.24%，结果 22.2%；不能把已舍入的行再相加成 22.3%。

## 验证和耗时记录

`python3 03_再刷重制_Godot/07_开发环境/测试合并工具.py`：所有 Git 写入、冲突与删除都发生在一次性临时资料库，覆盖新增用例、来源变更/失败拒绝登记、进度只舍入一次、干净工作区保护、冲突、重复接续、人工登记、检查失败和清理边界。检查.sh 已接入。

`CHECK_LOG_DIR=<目录> 检查.sh --oracle` 会由并行测试.py 额外保存 test_timings.json，记录各场景实际耗时、通过状态、并行数和总墙钟时间，按最慢优先排列；不改计时速度、验证规则或测试覆盖范围。
