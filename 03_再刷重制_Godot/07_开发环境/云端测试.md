# 云端测试（Claude 云端会话）

云端容器没有本机的 Godot.app、转换产物和冻结正式源。用 `云端准备.sh` 补齐前两样后，Godot 测试与 `检查.sh` 能在云端跑；探针与 `--oracle` 要冻结正式源，从项目文件夹的备份还原后也能在云端跑，见「不靠 Mac 产物」。

**日常选测改用 GitHub Actions 分片并行**（用户 2026-10-30），见文末「GitHub Actions 分片并行」：Mac 只推代码和产物快照，Godot 场景在十几台云端机器上同时跑。

## 步骤

1. 取转换产物（`modes/xiyou/generated/`，不入 Git）：在连了 Mac 文件夹的会话里，在 Mac 主工作区打包到 `.git/` 下（不进 `git status`，不挡合并）：
   `cd 03_再刷重制_Godot/01_Godot工程 && tar -czf ../../.git/cloud_generated.tgz modes/xiyou/generated`，
   再把它传进容器（或放进项目文件夹 `/mnt/project-files/云端测试/generated.tgz`，以后的云端会话直接用）。用完可在 Mac 上删掉 `.git/cloud_generated.tgz`。
2. `bash 03_再刷重制_Godot/07_开发环境/云端准备.sh [打包路径]`：装 zsh，下载与[环境登记](./环境登记.json)同版本的官方 Godot Linux 版并校验 SHA512，解开产物，`--import`。最后一行是要 export 的环境变量。
3. `GODOT=… CHECK_JOBS=4 zsh 03_再刷重制_Godot/07_开发环境/检查.sh`（`检查.sh` 的 GODOT 可用环境变量覆盖）。

## 2026-10-18 首次实测

- 转换产物取自 Mac main（sync_stamp 2026-10-18T02:05，v0.28 测量不变），打包 192 MB；Godot 4.7.2.stable.official.ed1daf0bf，与 Mac 同一构建。
- Godot 测试 65/65 通过，4 核约 5 分 16 秒；参照守卫、共性验收、合并工具、内容覆盖等工具检查全部通过。
- 「文档与登记」一节在云端会报 49 条失效链接，都指向不入 Git 的本地文件（`04_验证/本地结果/`、`验证与备份/`、`02_再刷西游/现有资料库`、`当前Godot.app`、`/Users/...`），属环境差异，不是问题。
- 产物会随车道合并过期：同步过的分支要重新打包。

## 不靠 Mac 产物：云端自己同步（2026-10-20 实测）

产物打包过期、或要跑探针与 `--oracle` 时，用项目文件夹里的冻结正式源备份在云端重新生成：

1. 还原冻结正式源到不入 Git 的原位置：`cd 03_再刷重制_Godot/02_内容与素材/冻结正式源 && cat /mnt/project-files/冻结正式源/app.nw.tar.gz.part-* | tar -xzf -`（约 30 秒），再 `sha256sum -c --quiet /mnt/project-files/冻结正式源/files.sha256` 核 6577 个文件。
2. `cd 03_再刷重制_Godot/03_转换工具/mv_oracle && npm ci`（照 package-lock 装 jsdom、lz-string）。
3. `python3 03_再刷重制_Godot/03_转换工具/同步正式西游.py --app <还原的 app.nw> --no-register --full --no-import --accept-additions`：转换约 20 秒，34 个探针 4 核约 42 分钟（event_probe、smart_ai_probe 各占 30 分钟以上）；再 `--import`。
4. `检查.sh --oracle` 的两项默认读 Mac 路径会失败，另跑：`XIYOU_APP=<还原的 app.nw> node boot_check.cjs`（在 mv_oracle 下）与 `python3 验证西游来源.py --app <还原的 app.nw>`。

实测（main 794cae6 加本分支）：Godot 测试 99/99，4 核约 36 分钟；失效链接降到 26 条（同上，属环境差异）。

## GitHub Actions 分片并行（2026-10-30 起）

Mac 跑选测太慢（多条车道抢 4 个共用槽，一批 20/189 个场景要 35 分钟），Godot 场景改到 GitHub Actions 上分片并行跑。工作流 [godot-tests.yml](../../.github/workflows/godot-tests.yml)（名为「云端选测」），脚本 [云端选测.py](./云端选测.py)。选什么场景照旧由 [选测.py](./选测.py) 与[选测对照](./选测对照.json)决定，怎么跑、判通过照旧由 [并行测试.py](./并行测试.py) 决定（云端单场景超时放宽到 1200 秒，本机不变）。

### 怎么用（Mac 上，总装或车道）

0. 先估：`python3 03_再刷重制_Godot/07_开发环境/云端选测.py estimate`（不推送，打印场景数、片数、约用多少分钟额度）。
1. 同步过转换产物、提交好之后：`python3 03_再刷重制_Godot/07_开发环境/云端选测.py run`
   - 先把本工作树的 `modes/xiyou/generated` 做成快照推到 GitHub 的 `refs/ci/generated/<分支>`（与远端那份相同就不推；第一次约 400 MB，之后只传改了的文件）；
   - 再把 HEAD 推到 `ci/<分支>`，触发选测：基准是 GitHub main 与 HEAD 的分叉点，等同 `检查.sh --affected main`。
   - `--full` 推到 `ci-full/<分支>`，整轮；`--no-upload` 不传产物（产物没变时省时间；没有本分支快照就用 main 的）。
2. `python3 03_再刷重制_Godot/07_开发环境/云端选测.py wait <提交>`：等结果并打印汇总（通过 0、失败 1、超时 124）。结果放在 `refs/ci/results/<提交>/<affected|full>`，只用 `git ls-remote`／`fetch` 读，不用 GitHub 令牌。失败场景的完整日志在运行页附件 `logs-shard-<片>`。
3. 总装合并：照常在 Mac main 合并、跑文档与登记检查和非 Godot 检查；Godot 场景用 `run`（当前分支是 main 时推到 `ci/main`）＋`wait` 代替本机 `并行测试.py`。通过后照常推 main（推 main 不触发云端，不会重测）。

云端线程也能手动触发（Actions 页「Run workflow」，或 GitHub 工具 `actions_run_trigger`）：可选整轮、改基准、强制重跑（同一提交测过并通过默认跳过）。

### 只在云端跑的部分

- 只跑 Godot 场景。`选测.py` 选中的非 Godot 检查（guards、tools、content、same_source）和文档与登记检查仍在 Mac 上跑，运行页摘要会列出选中了哪些。
- 转换产物不入 Git，云端用 Mac 推上来的快照。车道改了转换器而没推自己的快照时，云端用 main 的快照，内容相关的场景可能和本机结果不同（运行页摘要写明用的是哪份）。

### 怎么分片

- 计划任务（约 10 秒）按选测结果列场景，按耗时（先用 Actions 缓存里上次云端实测，没有就用 [云端测试耗时.json](./云端测试耗时.json) 的 Mac 实测 × 1.5）以「最长的先放进最轻的一片」分片；片数 ＝ 总耗时 ÷（每片 2 个并行 × 600 秒），最多 16 片。每片一台 2 核机器。
- 云端 Ubuntu 机器没有中文字体，`core/game_font.gd` 的回退字体（PingFang SC 等）落空，生僻字宽度会变（`xiyou_inlay_book`、`xiyou_status_power` 因此失败过）：`云端选测.py godot` 在云端装文泉驿正黑，随 Godot 进缓存。
- 准备任务解开产物快照、`godot --import` 一次，连同导入缓存存进 Actions 缓存（键＝快照＋工程文件指纹，同样的就直接命中）；各片取缓存直接跑。
- 汇总任务合并各片结果，写运行页摘要，推结果 ref，更新云端耗时缓存。

### 分钟数（私有仓库，每月 2000 免费分钟）

| 整轮 | 258 | 13 片 | 17 分钟（准备 3 分钟＋最长一片 14 分钟） | 约 155 分钟 |

### 回退

- 不用了：Mac 上照旧跑 `检查.sh --affected`，不受影响；删掉 `.github/workflows/godot-tests.yml` 即停用。

### 合并收尾与车道自测接云端（`--cloud`）

不用手工 `云端选测.py run`／`wait`：`检查.sh --affected <基准> --cloud` 把选中的 Godot 场景交给云端（推 HEAD 到 `ci/<分支>`、等 `refs/ci/results/<HEAD>/affected`），其余检查照旧在本机；`合并车道.sh <任务> --finish --affected --cloud` 在合并收尾时同样用它。云端只测**已提交**的 HEAD；基准是 GitHub 上的 main。`CHECK_CLOUD_NO_UPLOAD=1` 跳过转换产物上传（合并工具在本批没有切片／参照刷新时自动设），`CHECK_CLOUD_TIMEOUT=秒` 改等待上限（默认 3600）。推送失败、超时、未通过都判检查失败并提示改用本机（去掉 `--cloud`），不会悄悄回退到本机跑。自测用 `XIYOU_CLOUD_SCRIPT` 指向桩脚本（`测试选测.py` 覆盖通过、未通过、超时、触发失败）。
