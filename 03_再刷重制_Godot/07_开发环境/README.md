## 共用工具

- `检查.sh [--oracle]`：提交前检查。验证 JSON、文档链接、开发编号三处一致，运行 `01_Godot工程/tests/` 下全部测试（任何 `ERROR:` 都算失败），可选启动 MV 参照引擎。
- `云端准备.sh`：Claude 云端会话里装 Godot Linux 版、解开转换产物，让 Godot 测试和 `检查.sh` 能在云端跑（`检查.sh` 的 `GODOT` 可用环境变量覆盖），见[云端测试](./云端测试.md)。
- `待核查.py`：由提交尾注（`核查: 待Codex|待Claude`）减去变更记录里的核查条目，生成待交叉核查清单，`检查.sh` 每次打印；规则见[文件职责与记录](../../00_项目管理/规则/文件职责与记录.md)「待交叉核查清单」。
- `变更记录分卷.py split`：总装合并时把较早的变更记录整条移进 `00_项目管理/变更记录卷/`；`--check` 供 `检查.sh` 核对历史只追加。
- `开发编号.py`：不带参数时显示开发编号；`bump "说明"` 递增编号，并同步 `开发编号.json`、`project.godot` 与 `build_info.json`。

- `并行测试.py`：并行运行 `tests/*.tscn`（主工作区默认 CPU 数一半、最多 6 个，worktree 里默认 2 个，`CHECK_JOBS` 可改；每个测试独立临时 HOME，不碰真实用户数据）。按上次耗时慢的先跑；所有工作树共用并发上限 `CHECK_GLOBAL_JOBS`（默认 CPU 数一半）；整轮运行时工程指纹没变就沿用上轮通过的场景、只重跑失败的（`--full`／`CHECK_FULL=1` 强制整轮，`检查.sh --full` 传过去）；共用状态（耗时、整轮结果、偶发记录 flaky.jsonl）在 `.git/xiyou_test_state/`。`检查.sh` 调用它；也可跟场景名前缀只跑几个专项（指定场景时不沿用）。单跑一个场景（在本目录下）：`python3 并行测试.py ./godot ../01_Godot工程 --full <场景名>`，如 `xiyou_floor_reach069`；不要裸跑 `godot --path ... tests/x.tscn`，那样读本机 `options.json`（真实 user://），会误报。
- `新建工作树.sh <任务名> [claude|codex]`：多会话并行时给一条车道建 worktree（分支 `<执行者>/<任务名>`，建在主工作区旁），并补齐引擎链接、`node_modules`、转换产物与导入缓存（约 25 秒）；`--补齐 <路径>` 只补齐已有 worktree，加 `--branch <新分支> [--from <提交或分支>]` 时先在该工作树里从 `--from`（默认 `main`）切出新分支再补齐（app 自建工作树的车道开工用这条，tools22）。补齐装的 main 提交守卫用主工作区那份 `装提交守卫.sh`（车道分支里改了守卫，合进 main 前不会先装上）。补齐复制了主工作区的 `generated/oracle` 时，`参照批次.py` 记下它来自主工作区哪一版切片；补齐结束和 `检查.sh` 跑 Godot 测试前都比对本分支切片，不同批（主工作区合进了新楼层而本分支没合）就提示先 `git merge main` 再补齐，或本分支改了切片时在本树跑 `同步正式西游.py`，免得 `xiyou_event_compare` 完整性项假失败。`清理工作树.sh <任务名>`：分支并入 main 后删除 worktree 与分支，本地临时输出随工作树删掉（用户 2026-10-23），主工作区同名旧 `worktree_<目录名>/` 一并删。规则见[多会话并行](../../00_项目管理/规则/多会话并行.md)。


- 完整测试日志：`并行测试.py` 不给 `--log-dir`（或 `CHECK_LOG_DIR`）时写到 `04_验证/本地结果/并行测试/<时间戳>/`（留最近 10 份），结尾打印目录，失败的场景另打印完整日志路径；`--quiet` 只打失败、偶发、提示与汇总（管道给 `tail` 时用）。检查会拒绝结果行损坏、通过数不足或零项用例。
