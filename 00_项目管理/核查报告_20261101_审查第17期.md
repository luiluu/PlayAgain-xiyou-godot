## P2：PushState 的虚空排除，原版不生效

- 位置：`battle_logic.gd` `_push_states` 开头 `XAlienBattle.has(u, "void") and XAlienBattle.attack_damage(skill)` 就返回。
- 原版：installDamageElementRuntime 的 makeDamageValue 包装往 `result._after` 推一个回调，里面写的是 `CodexAlienation.isAttackDamage(this)`。整个运行时注册函数里开了 `'use strict'`，结算 `part()` 用 `fn(r)` 直接调用，回调里的 `this` 是 undefined，`isAttackDamage(undefined)` 恒为 false。所以排除从来不生效：虚空角色打攻击伤害，照样挂 PushState／PushsubState。
- 实测（正式引擎，临时脚本在 scratchpad，不入库）：角色 1 学 1580，把 `CodexAlienation.has(角色, 'void')` 定成真，普攻敌人，掷骰 0.1。回调里 isAttackDamage 收到的参数是 undefined，敌人照样挂上 161（不定成虚空时也挂上，作对照）。重制这时不挂。
- pushstate_probe 没有虚空用例，所以专项没测出来。变更记录把这条写成照原版，没登记优化。
- 原版的意图看得出是排除（installAlienationAdvanced 的 applyItemEffect 对虚空攻击的 21／31／32 效果确实拦下了），按「原版代码本身的错先修再登记」处理。建议：保留排除，登记一条 O-待定，写明原版 `this` 写错、排除从来没生效；做成 static var 回退开关；探针补「虚空＋1580」一例作回退支参照。总装已按这个派了。
- 影响面：只影响带虚空异化的角色、伤害类型 1／2／5／6 的技能、身上有 PushState／PushsubState 标签的情况。RecPushState 只在值为负时挂，攻击伤害碰不到它。

## parammax1（含 rollback3）

- `final_clamp`＝`roundf(maxf(HP?1:0, minf(param_max, v)))`，和原版 installNativeYunshangRuntime 的 Game_Actor.param 包装末尾 `Math.round(Math.max(id===0?1:0, Math.min(this.paramMax(id), v)))` 一致。值先夹到 0 以上再取整，所以 JS 的 Math.round 和 Godot roundf 在负的半数上取整方向不同这件事，这里碰不到。
- 逆骨读 `param_before_alien(3)` 的那一层，原版 `old.call(this, 3)` 拿到的就是云裳包装之后的值，重制的夹值也放在这一层，对上了。
- **P3**：modules.json 的装入顺序里，小猫剑圣在 installImportedBalanceRuntime（第 20 个），云裳在第 31 个，所以原版是先乘小猫剑圣的倍率、再由云裳夹值。重制写成 `XCat.param(final_clamp(XActorModules.param(...)))`，夹值在小猫剑圣里面，和 actor.gd 里新注释、探针注释说的「导入平衡之后」也对不上。现在看不出差异：XCat 只管 178，专属模块不碰 178，传进来的已经是整数；XCat 自己又取整，还按 param_min／param_max 夹了一次。以后哪个模块对所有角色乘小数倍率时，就要把次序摆对。
- 回退支（O-030／042／076×4／085 从 const 改成 static var）：每个测试都在测完后把开关设回 true。O-076 的 `_gains` 按开关算期望值，两个开关都关掉时，期望就是参照原样。O-042 的期望值手算过：`a b"中` 里空格 1、引号 1、「中」3，一共 5，实际 7 字节。豁免清单删掉的 7 项和改动对得上。
- param_max_probe 5 例：甚尔暴君、不学暴君、低加值、饿狼上限、角色 1 超上限，回退支用的是暴君那例的生命、物攻、速度三项。

## fb830b96：event_compare 基线登记 m4e1p2／p3

- **理由站得住**。在参照引擎里实测：新局之后 `Star.Designation.ComLen` 是 undefined，`ChooseTitle()` 之后 `isCommonEventReserved()` 是 false，选项窗确实不会出现。ComLen 只在 Scene_Title.initialize 里设（等于当时的公共事件数，冻结源是 9019），参照探针不经过标题画面。designation_probe 自己调了一次 Scene_Title.initialize 补上这条公共事件，选择流程由它来比，所以基线放过这两页不会漏掉回归。
- **P3**：Map4 EV1 第 2 页在选项块结束之后，还有 20 条「开关 318、324～342 关」。原版的顺序是：预约 → 关开关 → 事件结束 → 弹称号选项；重制是当场弹选项，再关开关。称号公共事件不读这些开关，而且 Game_Map.setupStartingEvent 会先跑预约的公共事件、再看自动事件，所以结果一样。基线说明里写的「该分支后面没有别的指令」只对分支本身成立，建议改成「后面只有关开关，称号事件不读」。第 3 页的选项块后面确实没有别的指令。
- **P3**：基线 `match` 还是 5752，现在登记了 3 例，应该是 5750（这次是手改的，没走 `--update-baseline`）。测试只读 `mismatch`，不影响判定。
