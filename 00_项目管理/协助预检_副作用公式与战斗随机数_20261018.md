## 4. 当前实现风险与 MV 依据

1. `core/damage.gd:19` 的 `eval_formula` 表面是求值，现通过 `XCustomDamage.evaluate` 会修改目标资源。它还被 `calculate`、`_healing`、`_mixed_weights`、战力面板和智能AI预览调用。当前三条净化之雷在 CodexDamageElements 的 mode 均为 magical，**没有证据说明这三条已经因mixed重复扣血**；但一旦复制到mixed技能、外部预览直接调用，框架会把求值当执行，且 `_mixed_weights` 额外计算三次。不得扩大硬编码覆盖。
2. 当前 `custom_damage_probe.cjs` 的48例只测真实 `evalDamageFormula` 的value／资源／阵亡／immortal，没有测完整 `Game_Action.apply` 的 ActionResult、弹字队列、反击反射、重复段数、混合权重与预览。迁移应保留48例，再补完整路径。
3. 净化之雷原文中 `b.gainHp(-3000)` 后才读取MP、TP；refresh可能先附死亡、清状态、改变上限。`value`先写MP的一半又被TP的一半覆盖；`tp = Math.min(hp,cap)` 是在后续 `var tp` 提升后的局部赋值。错误的「先抽所有式子、最后统一effects」会改变语义。
4. MV `YEP_DamageCore.js:1353` 在try中eval、失败返回0，不回滚此前已发生的副作用；语法编译失败和执行中异常须分开。普通公式与custom块的返回规则也不同。
5. `installDamageElementRuntime.js:97` 的 mixed 权重重算会再次运行公式，并复用随机抽样；本源没有当前混合副作用块实例。方案不能声称「执行一次effects、权重纯计算」已经兼容任意未来mixed副作用。遇到该组合先标unsupported，补oracle确认源语义或登记用户认可的修正。
6. 冻结 `LGP_BetterDamagePopup.js:574` 的 startDamagePopup 会按result中HP、MP、TP分别入队。gainHp/gainMp/gainTp写的是MV结果槽（同资源后写覆盖），与最终实际净变化未必相同；不能以最后damage.value覆盖掉所有副作用结果，也不能未经决定就把每条gainHp额外弹一次。
7. manifest现 `formulaUntranslatedInSlice` 为857、1068、4013、5455；净化之雷仍被记作未翻译，因支持只在runtime特例，不在转换器。5455是其他只读／流程语法问题，不属于31块清单。报告的「已支持」应由转换产物可执行能力和测试覆盖决定，不能在报告端按技能号减三。

8. 冻结 `ShieldSystem.js:117` 另包装gainHp：负值先吸收护盾，溢出伤害再按DAMAGE_REDUCTION衰减；setHp同样有保护（132行），`addShield`还应用ShieldEffect加成（85行）。所以资源mutator不能把任意gainHp都实现成裸HP夹值。当前48例未设盾，结论仅覆盖无盾资源语义；护盾系统接入后需复用完整钩子链并补盾小于／等于／大于扣量、溢出减伤、结果槽和状态刷新参照，再宣告带盾能力支持。

## 5. 战斗随机数调用链审计

以下是实际规则依赖点，独立 RNG 不能只替换 battle_logic.gd 内出现的随机函数：

| 模块 | 用途／跨模块路径 | 所有权审计结论 |
| --- | --- | --- |
| battle_logic setup | 初始TP、开战状态概率、随机队友／敌人／全体目标 | 本场规则流；setup开始前必须已注入 |
| enemy.setup/setup_level | 神话判定、敌人等级；神话色相另抽一次randf_range | 神话／等级用规则流；色相是演出，不能消耗规则流 |
| battle_logic _random_target/enemy_action | TGR加权目标、rating候选抽选 | 规则流；AI估算不抽，实际选招才抽 |
| _sorted_by_speed/make_action_times | OTB当前／下回合速度、追加行动概率 | 规则流；稳定同速排序和首次双排顺序保持 |
| _invoke/_apply/_effect | 魔反、反击、命中、闪避、暴击、附加／移除状态 | 规则流；概率为0或1时现代码仍抽的场合要保留抽样次数，不能顺手短路 |
| battle_logic.try_escape | 按_escape_ratio抽样，失败加0.1；OTB失败只耗当前角色本次行动 | 规则流；概率达到1仍抽样，不被画面等待扰动 |
| damage.apply_variance | 两次整数抽样的三角浮动 | 注入规则流；不得改成一次均匀分布 |

| battler.add_state | minTurns到maxTurns抽状态时长，包括死亡refresh间接调用 | 必须拿到当前战斗上下文；不能仅改显式apply几率 |
