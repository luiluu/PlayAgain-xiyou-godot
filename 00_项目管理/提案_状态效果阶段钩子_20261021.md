# 提案：状态效果阶段钩子＋js 效果再翻译（Claude·悟空，待沙僧审）

2026-10-21，悟空_32／33。本提案按规则属「基本框架」，先作 Claude 提案，交沙僧（或用户）审；审过再派实现车道。**本轮只写文档，没有改任何游戏代码、切片、探针。**

## 0. 结论先行

- 状态备注里的 `<Custom … Effect>` 转换器已解析成 `states[].effects[]`（`{phase, op, …}`），但只有两种形状翻译成结构化 op：`mul`（125 条）与 `user_param_damage`（2 条）。其余 **511 条是 `op: "js"`＝未翻译**，Godot 只读 confirm／react 的 `mul`（`damage.gd:326 apply_state_effects`）和 establish 的 `user_param_damage`（`battle_logic.gd:1237`），其余 phase 一概无人调用——**不是「没翻译好」而是「没有钩子」**。
- 全库 19 个 phase；原版 YEP_BuffsStatesCore 在其中绝大多数时点调用（§2 逐项列行号），Godot 现在只接了 confirm／react（`mul`）与 establish（`user_param_damage`）三处。
- 511 条 js 归并成约 14 个语义族（§1.2）。**只做「6 个声明式 op」就能覆盖其中约 70%**；剩下的（叠毒、状态计数器、战斗图替换等）要有状态私有数据，单独一期。
- 实现拆 5 期（§6），第一期只搭「分发框架＋未翻译清单」，不翻译任何 js，先让所有 phase 有挂点、`mul` 之外的 op 走统一入口。
- 不可翻译的 js 一律记入「未翻译清单」（不静默跳过）：战斗里照 `troop_event_skipped` 的做法记录，`检查.sh` 的测试可对清单设上限（只许减少）。

读源时的注意点：

1. `typestates(type)` 是按类型缓存的状态列表，`need_refreshstatelist[type]` 在加／去状态时标脏（krz）。**Godot 不需要缓存**，每次从 `states()` 里过滤带该 phase 效果的状态即可，但遍历顺序要与原版 `states()` 一致（`_sort_states` 已按优先级排序，沿用）。
2. 原版 `customEffectEval` 里 `user`／`target`／`a` 都是持有者；confirm／react／establish／respond 的 `value` 是返回值，`this` 是 `Game_Action`（`this.isHpEffect()`、`this.isAttack()`、`target.result().critical` 都可用）。
3. `regenerate` 是唯一对每条效果清结果槽并弹字的 phase。
4. `krz_state_re.js` 覆盖了 `gainHp`（73 行）、`addState`（130 行）、`removeState`（136～143 行），**包的是同一个原函数**，不改变上面的相对顺序，但 `gainHp` 的结果槽（角色记原值、敌人记减免后）已由八戒_39 的护盾交付处理，状态效果里的 `gainHp(-x)` 必须走同一路径（§7）。

## 4. 不可翻译 js 的兜底

1. 转换器：未命中任何形状的效果仍写 `{phase, op: "js", source}`，并在 `manifest.json` 加 `stateEffectsUntranslated`（总数、按 phase 计数、**切片内状态号列表**），与现有 `formulaUntranslatedInSlice` 同口径；`内容覆盖检查.py` 把「切片内可达的 js 状态效果」当成待翻译项，基线只许降。
2. Godot：`XStateEffects.run(phase, …)` 遇到 `js` 不执行、记入 `battle_logic.untranslated_state_effects`（`{state, phase}` 去重），与 `troop_event_skipped` 平行，测试可断言「此用例没有未翻译清单」（如错误数据 1741～1749 翻译完之后）。
3. 游戏里不弹提示（玩家无感），仅测试／日志可见。
4. 不用「Godot 内置 JS 解释器」兜底：与「规则改动先有 mv_oracle 参照」冲突，也不可验证。

## 5. 永久 addParam 的存档字段

- 原版：`Game_BattlerBase.addParam(paramId, value)` 写 `_paramPlus[paramId]`；`paramPlus` 在 `Game_Actor`／`Game_Enemy` 里与装备加成相加。该数组随角色存档，战斗内外都保留（奈叶 1768／10168、状态 1612）。
- Godot：`XActor.param_plus(i)`（`actor.gd:415`）现在只含装备、套装、法宝、`<Custom Parameters>`，**没有角色自身的永久加成字段**。建议：`XActor` 加 `param_perm: Array[float]`（8 项，默认 0），`param_plus` 末尾加上；`XActor.to_dict／from_dict` 与 `XState.to_dict／from_dict`（`xstate.gd:437／458`）读写，缺省补 0（旧存档兼容）；敌人不需要（战斗内临时即可，战斗结束丢弃）。
- 与 dev.117 变身缓存的交叉：改 `param_perm` 必须标 `param_mark_dirty()`，否则缓存读到旧值（`start_turn` 里 `param_refresh` 的时点）。
- 验收：mv_oracle 取一例「`addParam(0,10)`后 `param(0)` 增 10，`recoverAll` 不丢，存档往返一致」；Godot 存档往返测试。

## 6. mv_oracle 参照怎么取样

新探针 `mv_oracle/state_effects_probe.cjs`（只写 `.sandbox/state_effects.json`，同 `troop_event_probe` 的真实 `BattleManager`＋固定 `Math.random`，不跑动画）：

- **每个 op 至少一例**，选「切片内状态」优先（见 `状态效果形状统计.json` 的 `states`），再补一个切片外的同形状状态证明形状覆盖而非单状态。
- 例子的构造：给角色或敌人直接 `addState(id)`，驱动对应 phase（`onTurnStart`／`onTurnEnd`／`regenerateAll`／`startAction`／`endAction`／一次 `Game_Action.apply`），记录：持有者 HP／MP／TP／状态集／`_paramPlus`、目标结果槽与弹字、`$gameVariables` 变化、`$gameTemp` 的预约公共事件、伤害 `value` 的链式改写结果。
- **phase 顺序例**：同一行动里给攻击者与目标各挂一个记录用状态（只写变量），确认 initiate→select→(apply)→deselect→conclude 与 confirm→react→(扣血)→respond→establish 的相对顺序，与 §2 一致。
- **条件例**：随机条件固定 `Math.random=0.5`（命中分支）与 0.99（不命中）各一例；暴击条件用 `actionForceCritical`。
- 同步工具：`oracle_additions.py` 的 `KEYS` 加 `state_effects.json: {'cases': ('state','phase','variant')}`，新增例才算新增；探针路径与慢探针分片参照 `troop_event_probe`。

## 9. 风险与取舍

- **最大风险是顺序而不是翻译**：原版 15 个 phase 的相对时序（尤其 `krz` 的标脏与 `refresh` 时点）已有多处靠实测对出来（`start_turn` 注释里的 krz 说明），框架第 1 期就要用探针把顺序固化，否则第 2 期翻译再多也会在边界上错。
- **战斗图替换占 142 条但与结果无关**：不要拿它撑「覆盖率」，验收口径用「影响战斗结果的 js 条数」（511−142＝369）。
- **在切片外的 400 多条**：第 2 期之后再随扩切片逐步验证，不要一次性全部接线；`manifest` 清单保证「没翻译的不会静默当成翻译了」。
- 备选方案（不推荐）：不做框架，每个角色模块各自在 `battle_logic.gd` 里加专属钩子。短期快，但 108／1741／导入平衡会各加一套，且 500 条状态效果永远是黑洞。
