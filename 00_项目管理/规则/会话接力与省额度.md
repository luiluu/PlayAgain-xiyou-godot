# 会话接力与省额度

移自 [AGENTS.md](../../AGENTS.md)（2026-10-18 拆分，正文未删）。

## 会话接力（用户 2026-10-15）

每位工作者（总装或车道）都自动接力，不等用户开新对话：

- **一个会话只有一位工作者**：开会话时就定好是谁，中途不换人；要做别的工作者的事，就交给那位工作者的会话。
- **命名**：会话名 `重制_<工作者>_<序号>`，如 `重制_唐僧_1`、`重制_悟空_3`、`重制_沙僧_2`。序号按该工作者自己的会话从 1 递增，取侧边栏已有同名会话的最大序号加 1。Claude 会话放在侧边栏「Godot_再刷重制」分组。会话名写进车道表「工作者」栏和变更记录。
- 名册之前的会话已按主要工作归档改名（2026-10-15）：原「重制_1」（dev.011 说明卡）→ 重制_八戒_1；原「重制_2」（dev.016 地图 HUD、dev.017 传送页）→ 重制_八戒_2；原「重制_3」（dev.034～035 扩楼层）→ 重制_悟空_1；制定本规则的会话 → 重制_唐僧_1。
- **上下文到 40% 就接力**（用户 2026-10-18 由 50% 提前，省额度）：每次检查点提交时看一下上下文用量（Claude 用 `get_usage` 读 `context.percentUsed`；Codex 看自己客户端的上下文显示）。到 40% 时，把当前这一小步做完或以 `WIP:` 提交，写好接手说明——总装写交接板车道表，车道写交付单的「状态」，写明做到哪、下一步、未提交的东西（应为无）。然后在**同一个工作区**开新会话，命名为下一个序号，交代「按 AGENTS.md 开工，接着做 <任务>，上一会话 <会话名>」，旧会话就此停下。新会话照 AGENTS.md「开工」或[多会话并行](多会话并行.md)的「车道开工」读现场后继续。
- **接近额度就收尾**：每次检查点也看额度（Claude 看 `get_usage` 的 5 小时与每周额度）。5 小时额度用到 90%、或周额度用到 98% 时（用户 2026-10-21：周额度不用顾虑，照常派活，到 98% 才收尾、不再派新活）不再开新的小步骤，把手头这一步做完；做不完就 `WIP:` 提交，然后照 AGENTS.md「收工」（车道照[多会话并行](多会话并行.md)的「车道交付」，未完成就写「进行中」）更新交接板或交付单并提交，不再接力。注意 Claude 额度是**账号共用**的，唐僧、悟空、八戒会同时到线，三位都要收尾。
- **沙僧接力**：Claude 三位都收尾后，由用户叫沙僧（Codex）接力：先照车道表把可合并的交付单合并（暂代唐僧），再进优先级最高、状态为「进行中」的车道 worktree，按交付单接着做（先悟空的内容车道）。接力期间提交写 `执行者: Codex（沙僧）`、`核查: 待Claude`，交付单「车道／工作者」改成沙僧并写明接手点。Claude 额度恢复后，沙僧在交付单写好停在哪里并提交，交回原车道，自己回到核查。
- 接力和收尾都不能丢未提交的改动；开新会话前工作区必须已提交。

## 省额度约定（用户 2026-10-18）

会话越长，每一轮都要重新带上前面的上下文，后半段最费额度。所以：

- **早交接**：上下文到 40% 就接力（见上节）。
- **交接板精简**：交接板只留当前状态和下一步；已完成的协助计划项、已定事项、划掉的条目挪进[交接板归档](../交接板归档.md)（只追加，详细历史仍在变更记录）。总装每次合并后顺手清一次。
- **努力程度**：悟空、八戒车道默认中等；唐僧的常规步骤（合并、跑检查、登记）也用中等，遇到冲突、测试失败或设计判断时再提高。
- **少读大输出**：`检查.sh` 只看结尾的失败摘要；长日志、长差异、整份报告交给子代理读，只把结论带回对话。
- **续会话先压缩**：同一会话要接着干时先 `/compact` 再继续。
- **掉线后逐个恢复**（用户 2026-10-18）：Mac 掉线或额度中断后，不同时恢复多个会话——先恢复唐僧，车道等唐僧派活或合并时再叫；上下文已经很长的会话恢复前先 `/compact`，或按交接板开新会话接手。原因：掉线超过几分钟缓存失效，每个长会话恢复时都按全价重读整段上下文，三个同时恢复一下用掉约 18% 额度。
- **决定攒批**（用户 2026-10-18）：车道遇到要用户定的事，写进交付单「需要用户决定」后按自己的默认继续干，不停下来等；总装合并时并入交接板「需要用户决定」，攒够一批（或进度审查时）汇总成一份清单请用户一次拍板。
- **同步提速**（用户 2026-10-18）：互不依赖的探针并行跑（地图事件探针仍在转换之后）；合进来的 main 没改转换工具、切片和探针时不重跑同步，现有指纹仍有效；两条车道的同步尽量错开，不同时跑。
- **试行 Sonnet**（用户 2026-10-18）：下一批副本由悟空用 Sonnet 做，唐僧合并时记对照通过率和返工次数，与 Opus 批次比较后再决定是否扩大；唐僧总装与战斗、真气、变身等复杂系统继续用 Opus。云端并行车道暂不采用（项目云端额度 2026-10-18 到期）。
- **车道模型与强度按任务难度**（用户 2026-10-22）：机械的扩楼层、扩角色、文档类用 Sonnet＋medium；复杂系统（专属模块、新框架接线、读原版插件补参照）用 Opus＋medium；只有架构设计或疑难排查用 high。总装 `start_session` 开车道时必须显式传 `model` 与 `effort`，不传就继承总装自己的 high。车道表「工作者」栏写上模型／强度。
