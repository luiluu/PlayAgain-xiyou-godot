## 变更记录格式

```
## 日期 【执行者·未经X检验】标题

- 做了什么（用户方向变化先写）
- 验证：检查.sh 结果＋额外实测
- 提交：<提交号>
- 未完成／已知问题
```

核查结论另起一条：`## 日期 【核查者】核查 <提交号>`。
标题里「】」后紧跟「核查」，正文写清提交号、分支名或开发编号，`待核查.py` 才认得出（见下）。

## 变更记录分卷（2026-10-18 起）

当前卷 `变更记录.md` 只留近期条目，较早的整条移进 `变更记录卷/变更记录_<首日>至<末日>.md`（只读，条目原文不改，只调整相对链接）。

- 由总装在 `main` 合并时运行 `03_再刷重制_Godot/07_开发环境/变更记录分卷.py split`（默认保留最近 2 个日期，`--keep-days N` 或 `--before YYYY-MM-DD` 可改，`--dry-run` 先看）；当前卷超过约 150 KB 时做一次。车道不分卷。
- 只追加的检查改为「分卷＋当前卷连起来」与 HEAD 比较：既有条目只能原样留下或整条移进分卷，最后一条可以续写（`变更记录分卷.py --check`，`检查.sh` 调用）。
- `检查.sh` 的链接与占位检查只扫当前卷，不扫分卷。

## 待交叉核查清单（2026-10-18 起）

`03_再刷重制_Godot/07_开发环境/待核查.py` 列出 `main` 上带 `核查: 待审查` 尾注（旧写法 `待Codex|待Claude` 照计；审查线程自己的分支合并写 `核查: 无`，不计）、还没被对方核查条目覆盖的提交，按批（一次合并连同分支提交与收尾提交算一批）显示；`检查.sh` 每次打印，并按它计「核查积压上限」的批数（只改文档、登记的批单列，不计入）。

- 核查条目覆盖规则：审查条目（标题带「审查」，或有「核查者: cc（审查）」行）可销一切待核查尾注；旧写法下 Codex 写的核查条目只销 `核查: 待Codex` 的提交，cc 写的只销 `待Claude` 的。条目里写到的提交号销该提交；写到合并提交号、分支名或开发编号（`dev.NNN`、`dev.A～B`、`dev.A／B`）销整批，分支名与开发编号只销核查当天及以前的批。
- 核查有问题、修复还没合并时，问题写在交接板遗留问题里；修复提交带自己的尾注，会重新出现在清单上。
- 交接板的「待交叉核查」表暂时保留（合并工具仍按它确认登记），以生成的清单为准；两边对不上时按清单补核查或补登记。**表只留最近一批合并的行**（用户 2026-10-27 同意开工阅读瘦身）：下一批合并时总装把上一批的行移进交接板归档，不用等核完再删。

## 当前状态的字段（2026-10-18 清理）

`当前状态.json` 只留两类字段：工具自动维护的，和不会变的环境事实。不再手写阶段状态（看[重制步骤清单](../重制步骤清单.md)）和转换范围（看来源登记与转换产物清单）。

| 字段 | 维护者 |
| --- | --- |
| `godot.developmentVersion` | `合并车道.py` 合并时（手动 `开发编号.py bump` 后要自己改，`检查.sh` 会核对一致） |
| `remakeSource` 的版本、指纹、文件数、转换器版本 | `同步正式西游.py` 登记时 |
| `progress.percent`、`progress.asOf` | `进度账.py --write` |
| `progress.lastReviewAtPercent`、`nextReviewAtPercent`、`reviewAtPercents` | 总装在进度审查或用户调整审查点后同步；进度核算本身不算新增阶段审查 |
| `original`、`godot` 其余字段、`existingMod`、`collaboration` | 环境变化时手改（如升级 Godot） |
