## 1. 状态效果 2b～2d 翻译与运行时：通过（P2-1、P3-4）

- **转换器**：三类新 op 都按整块或整串 token 白名单匹配。`value_steps` 有 4 种常量加成形状，`value_program` 有 35 个签名，`value_query` 有 4 个签名；其余仍留 js。翻译边界测试覆盖了追加语句、前置语句、拆开标识符、换 phase、改比较符这几类情况。我抽查了 1047／1048／1834／2711 的冻结原文，与 `MEASURED_QUERY_BLOCKS` 的 token 签名一致。
- **运行时**：
  - `value_steps` 在每组的独立 if 里都按更新后的 value 重新检查条件，暴击步只在 critical 时生效，与原版块结构一致。
  - `_query_value` 的四个查询：
    - 2711 的条件是 value>0 且目标为敌人且 hpRate<0.2（hp／mhp 都是 float，没有整除问题），用 ceil。
    - 1834 用的是出战成员（`actors`＝`battle_members()`），判断存活看死亡状态 1，不看 HP。
    - 1047／1048 的门槛是 value>0 且为 HP 伤害，元素取攻击方，forced 优先于 null，范围 1～15，结果去重。
  - 以上都与 query.native_blocks 的 3060 行参照一致，专项里的全部对照都通过。
- **上下文**：`_state_context` 让 apply 四段、Confirm／React、respond／establish 共用同一份资源、记录、变量、开关和 RNG。respond 的返回值会传给 establish，与 damage.full_chain 参照的 7→14→7→21 一致。`_damage_record` 在 `_damage_value` 前后保存并恢复，嵌套反射时也不会串用。
- **P2-1 预览缺变量得 NaN（运行时，留沙僧）**：
  - 原因：`PhaseValueProgram.run_phase` 用 `ctx.get("variables", {})` 当 v 池。实战路径传的是 `vars()`（`XState.variable_array()`，5000 格补 0），没有问题。但 `power.gd:578／581` 的 `XPower._expected` 调 `XDamage.finish(…, item, a, t)` 时没有传 ctx，v 池是空字典，读 `v[1181]` 得到 UNDEFINED，值就成了 NaN。原版 `Game_Variables.value` 是 `this._data[id] || 0`（rpg_οbjects.js:559），未设置的变量读作 0。
  - 复现：持有 1421 欧皇之证的战斗者，`run_one("confirm", a, st1421, {"value": 100, "execute": false})` 返回 nan。传入的变量里缺 1181 时同样是 nan。
  - 影响：持有 1421／1422／1424／1259／1726／1733（永久状态，块里读变量 1181／1184／206／967／965／966）的角色，战力循环 `XPower._cycle` 的期望伤害会变成 NaN，战力显示和技能排序都会出错。实战伤害不受影响。
  - 为什么专项没测出来：value.native_blocks 每组参照都显式设置了全部 7 个变量，预览测试也都传了 variables。1834 的队伍查询已经为“预览没有 ctx”写了 XState 兜底，变量这一路漏了同样的兜底。
  - 建议修法：`run_phase` 在 ctx 没有 variables 时退回 `XState.current.variable_array()`（没有 XState 就按 0），或者 v 池缺键按 0 处理以对齐原版的 `|| 0`；同时让 `power.gd` 的两处 finish 带上 `{"variables": vars}`。补一条“预览不传 variables，结果有限且等于变量为 0 时的值”的断言，最好再加一条原版“变量未设置”的参照。
- **P3-4**：`PhaseValueProgram._read` 只接了 states_count 和 hp_rate，其余读法返回 `unsupported_phase_read`，只诊断不报错。目前 35 块都在白名单内，不会触发；交付单已写明它不能当通用公式执行器。这里只记一笔，不需要动。
