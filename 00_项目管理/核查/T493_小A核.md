## 二、问题清单

### P1（退回必改）

#### P1-1｜发行包下可通过明文 JSON「导入存档」与旧档补签零门槛绕过兑换码，直接获得并佩戴「洪荒首证」「洪荒·阿夜」

- **对应验收**：1、2
- **涉及位置**：
  - `03_再刷重制_Godot/01_Godot工程/modes/xiyou/core/save_transfer.gd:18,119-138,156`
  - `03_再刷重制_Godot/01_Godot工程/modes/xiyou/core/save_seal.gd:426-448`
  - `03_再刷重制_Godot/01_Godot工程/modes/xiyou/core/honghuang_titles.gd:112-118`
  - `03_再刷重制_Godot/01_Godot工程/modes/xiyou/map/designation_plate.gd:64-67`
- **问题分析**：
  1. `XSaveTransfer.ACCEPT_PLAIN_IMPORT` 默认为 `true`（O-497，兼容 D28 存档封存前的老玩家明文备份）。在正式发行包（`XSaveSeal.active_now() == true`）里，任何玩家无需拆包、无需破解加密、也无需兑换码，只要手改任意一份明文备份 JSON（或构造合法最小存档 JSON），填入以下任一字段：
     - `"flags": {"honghuang_titles": {"titles": {"52": true, "53": true}}}`
     - `"designation": {"name": "洪荒·阿夜", "icon": 6428, "color": "#a9c8ff"}`（或 `"洪荒首证"`）
     再在标题页点击「导入存档」，`parse_import` 走明文分支原样放行，`import_to` 随即用**发行密钥**将其封存签名为合法 `.ksv`。导入后该档永久解锁或直接佩戴「洪荒首证」「洪荒·阿夜（阿夜专属，不可获得）」并展示流光。
  2. 桌面端若删除存档目录下的 `.sealed_v1` 并修改自动留底的明文 `save_<N>.json`，重启进入时 `XSaveSeal._migrate_dir` 同样会原样将伪造的 `flags.honghuang_titles` 和 `designation` 封存为合法 `.ksv`。
  3. `XDesignationPlate._paint` 与 `XHonghuangTitles.flow_style` 只比对 `s.designation.name`，未校验当前存档是否持有 52／53（`save_has`），导致即使不改 `flags`，仅改明文 JSON 的 `designation` 字段就能直接顶着流光专属称号出场。
  4. **关键前提（无 D37 兼容冲突）**：T493（2026-11-25）晚于 D28 存档封存（2026-11-15），正式发行包里任何合法兑换过 52／53 的存档导出时必定是签名封存格式（`kyo-remake-save-sealed-v2` / `.ksv`），历史上**绝无可能**存在封存前的合法明文备份携带 `flags.honghuang_titles` 或佩戴 52／53。因此清洗未签名明文导入／迁移中的 52／53 数据不会误伤任何老玩家备份。
- **修复建议**：
  1. 在 `XHonghuangTitles` 新增清洗方法（例如 `strip_unsealed(data: Dictionary)`）：当 `data.flags` 含 `FLAG_KEY` 时删去；若 `data.designation.name` 为 52／53 专属称号名则清空 `designation`。
  2. 在 `XSaveTransfer.parse_import` 的未签名明文分支（`XSaveSeal.active_now()` 为真且未走 `_parse_sealed` 时）调用 `XHonghuangTitles.strip_unsealed(data)`；在 `XSaveSeal._migrate_dir` 补签明文存档 JSON 写入 `.ksv` 前同样清洗（仅针对存档类 JSON）。
  3. 佩戴展示侧双保险：可在 `XDesignationPlate._paint`／`XHonghuangTitles.flow_style`（传入 `s`）或头顶／侧栏读取处校验——若当前佩戴的称号名属于 52／53 且 `XHonghuangTitles.on(s)` 为真但 `not XHonghuangTitles.save_has(s, tid)`，则不按专属流光显示（注意不要在 `ENABLED = false` 回退时破坏已存的 `flags` 与 `designation`）。
  4. 在 `tests/xiyou_honghuang_titles.gd` 补充实测断言：封存开启下，未签名明文导入伪造 `flags.honghuang_titles` 或 `designation = 洪荒·阿夜` 会被清掉；合法 `FORMAT_SEALED` 导出再导入完整保留 52／53 解锁与佩戴。

### P2（记入报告，建议随返修顺带处理）

#### P2-1｜`map_scene.gd` 用物理帧取模在 `_process` 中节流自动补发检查

- **位置**：`03_再刷重制_Godot/01_Godot工程/modes/xiyou/map/map_scene.gd:705-706`
- **问题**：在渲染帧回调 `_process` 里写 `Engine.get_physics_frames() % 30 == 0`，高刷屏单物理帧会连续调两次（好在 `check_clear` 幂等），低帧率时可能偶发跨过整除帧。旁边 `_check_milestone()`（第 933 行）已采用实例计数器 `_milestone_tick += 1; if _milestone_tick % 30: return`，建议统一用独立计数器节流。

#### P2-2｜`designation_plate.gd` 缓存签名未纳入回退开关与画面特效开关

- **位置**：`03_再刷重制_Godot/01_Godot工程/modes/xiyou/map/designation_plate.gd:47-52`
- **问题**：`_sig` 未包含 `XHonghuangTitles.ENABLED` 和 `XGraphics.fx_on()`。同地图内热切 `ENABLED = false` 或在菜单里关闭画面特效返回地图时，名牌不会立即触发一次重画（会停留在关特效前的那一帧而非静态基色／`t = 0.0`）。建议把这两个布尔值拼入 `sig`。

#### P2-3｜`honghuang_titles.gd` 重复称号分支返回值 `ok` 语义不一致

- **位置**：`03_再刷重制_Godot/01_Godot工程/modes/xiyou/core/honghuang_titles.gd:220-226`
- **问题**：若未来两条不同兑换码指向相同称号，兑第二条时 `got` 为空，返回文本已切为 `MSG_USED`，但 `"ok"` 仍返回 `true`（与第 217 行已兑换过返回 `"ok": false` 不一致）。建议改为 `"ok": not got.is_empty()`。

#### P2-4｜`洪荒兑换码.py` 覆写已有输出文件时未强制收紧权限到 `0600`

- **位置**：`03_再刷重制_Godot/07_开发环境/洪荒兑换码.py:95`
- **问题**：`os.open(a.out, ..., 0o600)` 仅在新建文件时应用权限位；若 `--out` 指向已存在且权限较宽（如 `0644`）的文件，权限不会被收紧。建议在打开后补一句 `os.fchmod(fd, 0o600)`。

## 四、「兑换前另存的同身份副本还能再兑一次」判定

- **结论：可接受**。
- **理由**：
  1. 单机离线游戏无云端核销服务器，存档本身（`XSaveSeal`）是唯一防篡改持久化载体；全局配置 `options.json` 明文且重装即失，强行写进全局配置既防不住删配置，反而会导致玩家换设备或读兑换前备份时永久作废兑换码。
  2. 兑换前另存的副本依然是**阿夜本人的同一份进度**（同一 `orb_seed`），换任意其他玩家的存档（`orb_seed` 不同）均无效；且称号为纯外观、无数值加成、不可交易，允许本人回档到兑换前副本时重新补兑属于合理的单机容错。
  3. 本项与 **P1-1** 性质完全不同：本项仅限于持有合法兑换码且匹配 `orb_seed` 的本人副本，而 P1-1 允许任何第三人无需兑换码直接白嫖专属称号。
