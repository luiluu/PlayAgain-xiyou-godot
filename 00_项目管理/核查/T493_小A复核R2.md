## 二、重点判定：只在封存开着时清洗（`XSaveSeal.active_now()`）可否

- **结论：可（合理且必要）**。
- **依据**：
  1. **发行包安全边界完整**：正式发行包出包时注入发行密钥且 `XSaveSeal.ENABLED = true`，`XSaveSeal.active_now()` 为真，未签名明文导入与旧档补签均触发 `strip_unsealed`；且 `is_template()` 下不认 0 号公开测试密钥，无法拿开发版测试密钥伪造封存档导入发行包。
  2. **避免破坏封存关闭时的正常导出／导入闭环**：当 `XSaveSeal.active_now() == false`（如回退关闭 `XSaveSeal.ENABLED` 或无密钥环境）时，`XSaveTransfer.export_text` 导出的是明文 `FORMAT`；若此时仍清洗明文导入，会导致合法兑换过 52／53 的存档导出再导入时自身称号被洗掉，且明文存档环境下本就不存在防篡改边界。
  3. **措辞小澄清（非缺陷）**：交付单把 `active_now() == false` 简称为「开发版」；实际上开发版默认 `ENABLED = true` 时因加载 0 号测试密钥，`active_now()` 默认也为 `true`（同样封存导出、清洗明文导入），仅在显式关闭 `XSaveSeal.ENABLED` 或无密钥 template 包时为 `false`。代码按 `XSaveSeal.active_now()` 分流本身逻辑严谨、完全正确。
