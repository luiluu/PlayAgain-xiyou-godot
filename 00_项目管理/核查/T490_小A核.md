## 二、关于验收 3「实际等级」与「实际生效等级」的口径核对

- **核心问题（会不会被折算误触发）**：**一致，无歧义**。无论「实际等级」还是「实际生效等级」，对比对象都是「折算后的战斗等级 `combat_level`」。`XMagicWeapon.item_skills`（`magic_weapon.gd:425`）没有接入 `combat_level`，继续读 1～99 级的未折算值，因此：
  - 9/19/29/39 级时不会提前领悟下一档（7510/7511/7512/7513），10/20/30/40 级时准确领悟。
  - 在正常游玩流程中（法宝升级受 `max_level` 限制，`level_of <= floor_cap`），`effective_level == level_of`，两者完全等价。
- **唯一边界差异**：当存档法宝等级高于当前楼层上限时（仅发生于老存档 888→99 迁移后，或星级仓库跨档取出高阶法宝放入低楼层档，例如 99 级烽舞处于 1 层上限 12 级）：
  - 按 `level_of`（存档原始等级）：99 级落在 `[40, 9999]`，领悟 7513；
  - 按 `effective_level`（实际生效等级）：1 层上限压为 12 级，落在 `[10, 19]`，领悟 7510（且注意 7510～7513 区间互斥，升层突破 20/30/40 级上限后自动进阶恢复）。
- **结论**：`item_skills` 使用 `effective_level` 是前序卡 T476（提交 `dfc8bc8ce`）确立的楼层上限口径，T490 沿用未改，与验收 2「超楼层上限按本层上限生效」一致，不构成缺陷；在此写明供协调留底。

## 三、九组样本独立复算（抽算 4 组）

核对基准：`03_再刷重制_Godot/01_Godot工程/tests/xiyou_fabao_99_scale.gd:95-103` 中 `CombatProbeActor`（`mhp=10000, mmp=1000, atk/def/mat/mdf/agi/luk=100`）、`CombatProbeTarget`（`mhp=1e8, 其余=50`）、`v[1165]=600, v[320]=600`，公式直接取自 `03_再刷重制_Godot/01_Godot工程/modes/xiyou/generated/db/Skills.json` 与 `States.json`。

1. **天虎令 · 红尘一步·烽火无尽（Skill 7485，防具 3550 烽舞，`cri=0.01`）**
   - 原公式：`((6000 + v[1165] + (user.atk*5 + user.mhp*3.5) * (70 + mastery*3.0 + level*3.0 + (1 + user.cri*3))) - target.def*2.0)`
   - 代入 `level = 99 × 888 / 99 = 888`：
     `6000 + 600 + (500 + 35000) × (70 + 0 + 2664 + 1.03) - 100 = 6500 + 35500 × 2735.03 = 97,100,065`
   - 交付单／实跑：`97,100,065` / `97,100,065`（比值 `1.000`，吻合）。

2. **曹操 · 霸道连环击（Skill 1068，防具 3640 暗涌）**
   - 原公式：`(750 + user.atk * 9.5) * (1 + level) - target.def * 2`
   - 代入 `level = 888`：`(750 + 950) × 889 - 100 = 1,511,300 - 100 = 1,511,200`
   - 交付单／实跑：`1,511,200` / `1,511,200`（比值 `1.000`，吻合）。

3. **小明 · 奥术波动·玄心（Skill 8087，防具 4996 玄心の屌丝，`elementRate(7)=1.0`）**
   - 原公式：`((600 + user.mat * (6 + level * 1) - target.mdf * 0.6) * (1 + damage * 1.5))`
   - 代入 `level = 888`：`(600 + 100 × 894 - 30) × 2.5 = 89,970 × 2.5 = 224,925`
   - 交付单／实跑：`224,925` / `224,925`（比值 `1.000`，吻合）。

4. **克莱德 · 毒奶术状态扣血（State 732，防具 3590 毒心，`stacks=2, v[320]=600`）**
   - 原公式：`Math.round(stacks * 0.5 * (mmp*8 + v[320] + mat) * (1 + level) * (1 + v[320]/3000)^2)`
   - 代入 `level = 888`：`round(1 × (8000 + 600 + 100) × 889 × 1.2 × 1.2) = round(8700 × 889 × 1.44) = 11,137,392`
   - 交付单／实跑：`11,137,392` / `11,137,392`（比值 `1.000`，吻合）。
