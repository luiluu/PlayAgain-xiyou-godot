## 二、问题清单

### P1（退回返修，2 条）

#### P1-1｜`03_再刷重制_Godot/01_Godot工程/modes/xiyou/core/tianqi_element_effects.gd:276-286`｜神圣对己方入口在真实数据库零命中，且装神圣转换书会误判任意己方技能｜对应验收 2
- **现象与证据**：
  1. `_skill_has_holy(skill, u)`（282～286 行）检查 `XTianqiElements.map_elements(XDamage.action_elements(skill, u))` 是否包含元素 `8`（神圣）。
  2. 全库扫描 `modes/xiyou/generated/db/Skills.json` 与 `modes/xiyou/tianqi_data/skill_rework.json` 中所有己方目标技能（`scope ∈ {7, 8, 9, 10, 11}`）：`damage.elementId` 分布为 `{0: 116, 10: 167, 4: 7, 1: 13, -1: 1, 7: 6, 6: 9}`，**带元素 8（含 `yep.multipleElements` 与 `elements_table.json` 的 `skill_shifts`）的己方技能为 0 个**。
  3. 游戏内全部真实神圣治疗／增益技能——例如拉尔的 `2318 圣光净化`、`2320 天堂光辉`，阿语的 `5512 仪式:苏生`，以及 `89/680 圣光术`、`649 光辉映照`、`1710 治疗祷告`、`2095/2099 超越之光`、`2690 神圣祷言`、`2824 光明护盾`、`5571 黄庭圣经`、`5779/5782 圣光救赎`——其 `damage.elementId` 全部填的是 **`10`（治疗）** 或 **`0`（无属性）**，而 `XTianqiElements.map_element_id(10)` 返回 `10` 不转为 `8`。
  4. 单元测试 `tests/xiyou_tianqi_element_effects.gd:473, 483` 用 `_stub(98560, 8, "10", 3, 7)` 构造了库中不存在的 `elementId = 8` 假技能，导致测试全绿而实机下神圣治疗触发圣护完全不生效。
  5. **反向误触发**：`XDamage.action_elements(skill, u)`（`modes/xiyou/core/damage.gd:82`）优先读取被动缓存 `damageElement`。若任意角色装备神圣转换书（`damageElement == 8`），其施放任何非神圣的己方增益／回血技能都会返回 `[8]`，从而误触发圣护。
- **修复建议**：
  - 梳理真实可用角色与技能池中的己方神圣治疗／增益技能，在 `elements_table.json` 中明确配置（如 `holy_ally_skills` 白名单或 `skill_shifts`；注意**不能**把全部 `elementId == 10` 统一映射为神圣，因为 `73 PUA`、`306 痛饮`、`329 野性能量`、`357 治疗波` 等非神圣恢复技也是 `10`）。
  - `_skill_has_holy` 改读技能原生元素（`XDamage.original_elements`）加配置表，不被攻击用转换书误覆盖。
  - 单元测试补充使用真实数据库技能（如 `2318 圣光净化`、`2320 天堂光辉` 或 `680 圣光术`）与「装神圣转换书用非神圣己方技不触发圣护」的断言。

#### P1-2｜`03_再刷重制_Godot/01_Godot工程/modes/xiyou/core/tianqi_element_effects.gd:268-279` 与 `03_再刷重制_Godot/01_Godot工程/modes/xiyou/battle/battle_logic.gd:2775-2785`｜魔法反射时序错位：反射拦截失效，且神圣攻击被反射打自己反而触发圣护｜对应验收 1、2
- **现象与证据**：
  1. `battle_logic.gd:2775-2785` 触发魔法反射／元素反弹时，先置 `_reflecting = true`，再调用 `apply(u, skill, u)`（其末尾 3092 行已执行 `XTianqiElementEffects.note_hit(self, u, skill, u, r)`），**直到 `apply` 返回后的 2785 行**才写入 `r.reflected = true`。
  2. 因此 `note_hit` 第 271 行 `var origin := "reflect" if bool(r.get("reflected", false)) else "skill"` 永远为 `"skill"`，反射标记从未生效（B2 放开 `_side_ok` 后反射段会误算合格段）。
  3. 更直接地，本卡当下即可复现实质缺陷：我方 `u` 对敌人施放**神圣伤害技能**（`dtype == 1`、`element == 8`），被敌人魔法反射或元素反弹打回自己 `u` 时，进 `note_hit(self, u, skill, u, r)`：第 268 行 `_side_ok(u, u)` 为 `false`，随即落入第 276 行「神圣对己方用」分支；此时 `u is XActor`、`_same_side(u, u)`、`not is_item`、`u.is_alive()`、`_skill_has_holy` 全部成立，**敌人反射回来的神圣攻击反而给施放者驱散减益并套上圣护盾**。
- **修复建议**：
  - `note_hit` 开头拦截 `if bool(logic._reflecting) or bool(r.get("reflected", false)): return`。
  - 第 276 行神圣己方入口同时排除伤害技能（如 `not (dtype in [1, 5])` 或限定己方 `scope`）。
  - 补充 1 条神圣攻击被敌人反射不触发圣护的反例测试。
