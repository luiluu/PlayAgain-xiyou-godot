## 2. 补齐后参照与切片不同批：改为记批次加提示

**原因（实测）**：
- `--补齐` 的 `refresh_oracle` 只把主工作区较新的 `generated/oracle/*` 复制进来。maps、manifest 由本分支的转换器按本分支切片重生成。
- 主工作区合进新楼层后，车道再补齐，就成了「参照是新切片、地图是旧切片」。
- 本树就是这种情况：主工作区切片指纹 eb29d971…，本分支 6d9754bd…，于是 `xiyou_event_compare` 的 `oracle_cases_complete` 报 4632 对 4645。

**为什么没有整份对齐主工作区**：
- maps、manifest、db 都是本分支转换器的产物，整份换成主工作区的，转换器跑完又会改回本分支的切片。
- 本分支落后 main 时，正确做法是先合 main 再补齐；本分支自己改了切片时，正确做法是在本树同步。整份覆盖会把这两种情况都掩盖掉。
- 所以按派单给的第二种方案做：记批次，检查时提示。

**改法**：
- 新工具 `07_开发环境/参照批次.py`：
  - `record`：补齐复制了主工作区参照（至少一份，或首次整份克隆）时，写 `generated/oracle_batch.json`，记下主工作区 manifest 的 `sliceConfigSHA256`，以及本树当时的同步戳 `sync_stamp.outputsDigest`。
  - `check`：比对本分支 manifest 的切片指纹。不同批就打印提示，退出码 3：
    - 本分支落后 main：先 `git merge main`，再 `--补齐`；
    - 本分支改了切片：在本树跑 `同步正式西游.py`。
  - 不提示的情况：本树之后自己同步过（同步戳变了）；没有批次记录，比如主工作区或从未补齐过的树。
  - 一开始用主工作区的同步戳判断「本树自己同步过」，但重复补齐不会刷新 `sync_stamp.json`（它不在 oracle 目录里），本树实测会漏报。改成记本树自己的戳以后，本树能正确报出不同批，回归测试里也加了这个例子。
- `新建工作树.sh`：
  - refresh_oracle 记下复制了几份，复制过才调用 record；一份都没复制时不改写已有批次。
  - 转换器跑完立刻调用 check，只提示，`|| true` 不中断补齐。
  - 免权限弹窗的用法（app 自建 worktree 后用 `--补齐 <路径>`）完全没变。
- `检查.sh`：只在确实要跑 Godot 测试的分支里，于导入前调用 check。只提示、不判失败；只改文档时不调用。
- README 的 `新建工作树.sh` 一条补了说明。

**回归测试** `07_开发环境/测试参照批次.py`，9 项，已挂进 `检查.sh` 的工具回归：
- 同批不提示；

- 本树自己同步过不提示；
- 没有记录不提示；
- 主工作区没有指纹时不记；
- 用法错误；
- 接线顺序（复制 → record → 转换器 → check），以及 `检查.sh` 的不判失败写法。

反向验证：把比对改成恒等后，测试失败。

## 3. 规则：反向验证不用 `git checkout -- 文件`

`00_项目管理/规则/项目边界与操作规则.md` 在 Godot 测试写法那条后面加了一条：
- 临时退回修复之前，先把修复提交成检查点，事后 `git checkout HEAD -- 文件` 回到检查点；
- 或者用 `git stash push -m <唯一标签>`，记下 SHA 再 `git stash apply <SHA>`，不用裸 `stash pop`。
