## 结论（一句话）

不是变速设置（`a20dafd17` 只缩放帧数）。是**读一次能力值就要重建整张技能表**，而这笔钱被三处改动越抬越高：①11-18 弱者专属词条（`bba3f291c`）在西游档也给每条技能建投影号表，技能表重建贵了约 9 倍（玩家现版 dev.893 已有）；②11-26 技能表跨调用缓存 O-677（`f8bdf569b`，补丁线 v0.04.07 已摘）让被动值绕过只读窗口、每次现算 id 表，这份存档上反而慢三成；③侧栏状态行没有快照时实时读最大 HP／MP／TP 不在只读窗口里（老写法，被①②放大）。T225 逐段结算（11-19）把结算放在动画之后的 ACTION EFFECT 上，四倍速动画变短、卡的那一截不变，所以玩家感觉「点技能释放之前卡」「越快越慢」。

## 2. 根因（哪次引入）

先在 main 第一父链上取点（11-14 → 11-24 每约 110 个合并取一点），逻辑基准每次行动 137（11-14）→ 143（11-16）→ 151（11-17）→ 159（11-18）→ 187（11-19）→ 242（11-20）→ 234～305（11-21～23）→ 276（11-24，dev.893）→ 约 370（11-27）：**是逐步累积，不是一次跳变**，所以改用 Godot 自带的函数剖析（`-d --profiling`）对比各版本的调用次数和耗时，找出三处大头：

1. **弱者专属词条投影（`bba3f291c`，11-18，T018 批 1）**：`XActor._skill_records` 每条技能都过 `XTianqiWeakAffix.skill_view` → `proj_of`，`proj_of` 先 `_proj_ids()`（把全部条目逐条 `entry`／`enabled` 一遍建号表）再判 `on(s)`（天启篇档）。西游档 40 次行动 `skill_view` 27.6 万次、`enabled` 220 万次，`_skill_records` 总耗时 0.60 → 5.39 秒（建记录的次数没变，5557 → 5204）。**玩家现版 893 就有**，是玩家这次觉得变卡的主要原因。
2. **技能表跨调用缓存 O-677（`f8bdf569b`，11-26，T546；补丁线 `55e7ae828` 摘入 v0.04.07）**：`_passive_values_now` 改成直接调 `_skills_entry()`，而 `_skills_entry` 每次都先现算一遍 id 表（各 skills 包装：心钢、云裳、异化、屠苏／璇逐条查归属、专武在不在……）来比对；原来走 `skills()`，在只读窗口／跨步保留里同一角色只建一次。40 次行动 id 表现算 5557 → 36501 次，单这一项 11.9 秒。核实：未修的 main 上 `SKILLS_XCALL = false` 每次行动 242～269 ms，`true` 327～338 ms——**这份存档上 O-677 原样反而慢三成**（T546 交付时量数用的是 400 被动的样本，那里 id 表便宜；玩家这支队伍 id 表每次要 0.3～0.4 ms）。玩家 893 没有，补丁线 v0.04.07 有，不修会进下一个补丁、比现在更卡。
3. **侧栏实时读数（老写法，10 月中旬起就这样）**：`XSideStatus._v()` 没有快照时（每次行动演完 `clear_views` 之后、输入指令时状态格每隔一会儿轮换重画）直接读 `actor.mhp`／`mmp`／`max_tp()`，不在只读窗口里，每读一次都重建整张技能表。①②之后单次读数变贵，清快照那一帧在 main 上 387 ms。**「菜单栏滑动也卡」对得上这一条**：手动输入指令、翻技能列表时侧栏照样轮换重画；另外主菜单技能页的同类问题 T545 已修（O-673，补丁线已摘）。

「越快越慢」：T225（11-19，O-609 逐段结算）把结算从「点完指令那一帧一次算完」改成「动画演到 ACTION EFFECT 再算这一段」。结算本身不随变速档变，四倍速时动画只剩四分之一，停住的那一截就显得更长，而且正好落在「技能放出去之前」。不是 T225 自己变慢（它只是挪了位置）。

查重：`git log` 里没有人修过这三处；T544／T545（技能页只读窗口）、11-13 几次战斗卡顿修复都是别的路径。

## 3. 修法（三个回退开关，默认开）

1. O-待定-1 `XTianqiWeakAffix.XIYOU_SKIP`（`core/tianqi_weak_affix.gd`）：`proj_of` 先判 `on(s)`，不是天启篇档直接返回空，不建投影号表。几项都是只读判断，换序结果不变；天启篇档照旧往下判。
2. O-待定-2 `XActor.SKILLS_ENTRY_HELD`（`core/actor.gd` 新 `_skills_entry_held`）：`_passive_values_now` 取缓存项时按 `skills()` 的规矩记进只读窗口（`_read_memo` 的 "ske0"/"ske1"）和跨步保留（`_carry_fetch`，与 `skills()` 的 "sk0"/"sk1" 同一作废时机）；窗口里命中时 `READ_VERIFY` 照旧现算比对。窗口外照旧 `_skills_entry()`。
3. O-待定-3 `XSideStatus.LIVE_WINDOW`（`battle/side_status.gd`）：`_v()` 没有快照时的实时读数包 `XActor.read_begin()`／`read_end()`（O-348 同款，只读）。新界面 `XSkinSideStatus` 继承同一个 `_v()`，一起受益。

另加两个只读计数给专项用：`XActor.skill_ids_builds`（`_skill_ids_now` 次数）、`XTianqiWeakAffix.proj_ids_builds`（`_proj_ids` 次数）。
