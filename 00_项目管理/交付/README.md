# 交付单

多会话并行时，车道不改交接板、变更记录、进度账等共用文件，要写进去的内容写在这里，由总装合并时并入后删除。规则见[多会话并行](../规则/多会话并行.md)。

- 文件名：分支名把 `/` 换成 `_`，如 `cc_六层.md`。每个分支一个文件（分支前缀 `cc/`；旧的 `claude/` 分支对应 `claude_<任务>.md`，照认）。
- `main` 上除本 README 外不应留有交付单；`检查.sh` 在主工作区会报出未并入的交付单。
- **交付前自检**：交付单写好、提交之后跑 `python3 03_再刷重制_Godot/07_开发环境/交付自检.py`（只读，十几秒），它照搬合并工具准备阶段的检查并对 main 试合并；退出码 0 再回报可合并（见[车道须知](../规则/车道须知.md)「交付自检必跑」）。
- **云端与截图**（交付自检会查，T403）：改了工程 `.gd` 的交付单要贴云端选测 run 链接（`…/actions/runs/数字`），没跑就明写「没跑云端」和原因；交付单里列的截图要提交进分支；起 Godot 的新增启动脚本一律带 `--audio-driver Dummy`。发回执前交付单＋自检 0＋`发行空壳.py check` 0 三样齐，云端选测用 `gh run watch` 前台等完再发。
- 状态行：合并工具只认「状态：可合并」这一行。macOS 的 sed 改原文件要写 `sed -i '' 's/^- 状态：进行中/- 状态：可合并/' <交付单>`（不带 `''` 会失败或留备份文件），或直接用编辑工具改。
- 草稿里的相对链接照交付单所在目录写（如 `../规则/多会话并行.md`，`检查.sh` 按这个口径核链接）；合并工具并入变更记录时自动改成变更记录口径。只有整行「待写」「（待写）」算未完成，正文提到这两个字不受影响。
- 车道路径行（可选）：车道不在 `git worktree list` 里（工作树没了、在 scratchpad 里 `git clone --shared` 的）时写一行 `- 车道路径：<clone 的绝对路径>`，合并工具核对该处分支头等于交付提交、干净后，拿它给同步的 `--from-worktree`／`--state-prev-from` 取车道产物（不写就照旧完整同步；`XIYOU_LANE_PATH=0` 不读）。交付后那个 clone 留到总装合并完再删。
- 接手者可在同一分支另写一张交付单（如 `<分支>_接续.md`）：标了可合并就随主交付单一并归并删除。

```markdown
# 交付：<分支名>

- 车道／工作者：A 内容·楼层／悟空（cc，重制_悟空_1）
- 状态：进行中｜可合并

## 变更记录草稿

（照 00_项目管理/规则/文件职责与记录.md「变更记录格式」写正文条目，标题如 `## 日期 【cc·悟空·未经审查】标题（dev.待定）`）
（玩家能看到变化的条目加一行 `- 玩家可见：……`，发行说明用它；见同一节）

## 交接板

- 下一步：要新增、改写或删掉的条目
- 用户试玩说明：本轮玩家能看到的变化
- 需要用户决定：（如有）

## 进度账

- 部分：完成度 旧% → 新%，依据一句话
- 冻结后的正式版改动（v0.29～v0.62.12 新增）和 Windows／安卓写扩展账，不写主表（审查 67 建议）

## 可优化（流程／工具／效率）

- 本轮发现的可优化项：已做的写「已做：…（怎么回退）」，没做的写「建议：…（预计收益、该归哪条车道）」；没有就写「无」

## 动了的共用函数和开关

| 函数／开关 | 调用方 N 处（附 grep 命令） | 逐处结论 |

| `XFoo.bar` | 12 处（`git grep -nE '[^[:alnum:]_]bar[[:space:]]*\(' -- '*.gd'`） | 调用方 N 处逐处结论（N 换成真实数字）：哪几处受影响、为什么不会被改坏 |

## 数值报告：逐种子分布（跑了多种子测量才写）

统计量：均值、中位数、最小～最大、标准差（写清样本数；有剔除的种子单列原因，不剔除要明说「全部计入」）。

## 本分支提交

- <提交号> 简述
```
