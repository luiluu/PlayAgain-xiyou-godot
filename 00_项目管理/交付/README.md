# 交付单

多会话并行时，车道不改交接板、变更记录、进度账等共用文件，要写进去的内容写在这里，由总装合并时并入后删除。规则见[多会话并行](../规则/多会话并行.md)。

- 文件名：分支名把 `/` 换成 `_`，如 `claude_六层.md`。每个分支一个文件。
- `main` 上除本 README 外不应留有交付单；`检查.sh` 在主工作区会报出未并入的交付单。
- 状态行：合并工具只认「状态：可合并」这一行。macOS 的 sed 改原文件要写 `sed -i '' 's/^- 状态：进行中/- 状态：可合并/' <交付单>`（不带 `''` 会失败或留备份文件），或直接用编辑工具改。
- 草稿里的相对链接照交付单所在目录写（如 `../规则/多会话并行.md`，`检查.sh` 按这个口径核链接）；合并工具并入变更记录时自动改成变更记录口径。只有整行「待写」「（待写）」算未完成，正文提到这两个字不受影响。
- 接手者可在同一分支另写一张交付单（如 `<分支>_接续.md`）：标了可合并就随主交付单一并归并删除。

## 模板

```markdown
# 交付：<分支名>

- 车道／工作者：A 内容·楼层／悟空（Claude，重制_悟空_1）
- 状态：进行中｜可合并

## 变更记录草稿

（照 00_项目管理/规则/文件职责与记录.md「变更记录格式」写正文条目，标题如 `## 日期 【Claude·悟空·未经Codex检验】标题（dev.待定）`）

## 交接板

- 下一步：要新增、改写或删掉的条目
- 用户试玩说明：本轮玩家能看到的变化
- 需要用户决定：（如有）

## 进度账

- 部分：完成度 旧% → 新%，依据一句话

## 可优化（流程／工具／效率）

- 本轮发现的可优化项：已做的写「已做：…（怎么回退）」，没做的写「建议：…（预计收益、该归哪条车道）」；没有就写「无」

## 本分支提交

- <提交号> 简述
```
