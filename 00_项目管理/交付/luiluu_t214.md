## 是 bug 不是设计

- 设计稿 `重制设定/天启篇_基础数值重构_v0.4.md`（私密仓）第七节表：「治疗 ×5｜开着：不乘｜关着：照乘」；第十节：「治疗 ×5 随总开关去掉」；风险表：「都开了，治疗 ×5 没去——卡里治疗按生命比例，再乘 5 就是一口回一管半」。
- 代码本意相同：`tianqi_base.gd` 头表「治疗 ×5｜不乘｜照乘」、`heal_skip_types()` 注释「开着时 HP、MP 回复（3、4）不再 ×5」（T081 e5bb47c89 引入）。
- 毛病在接线：`tianqi_no_diff_passive.gd confirm_rows` 把 [3, 4] 并进合成行的 `skipTypes`，而 `state_effects.gd _active` 认 `skipTypes` 时要求 **目标是敌人**（那是去全队 ×6 O-470 的口径：打自己人的混乱伤害照旧 ×6）。治疗打的是自己人，于是期四开着时我方所有走伤害公式的回复（HP 回复 type 3、MP 回复 type 4）都照乘 ×5。
- 原专项 `xiyou_tianqi_phase4` 的 `confirm_heal_x5` 只断言合成行的列表里有没有 3、4，没量真实结算，所以一直没抓到。

## 怎么改（一处）

- 合成行加一个键 `skipTypesAny`：放 `heal_skip_types()` 那两类，**不论目标**都跳过；`skipTypes` 只剩去 ×6 的 [1, 5]（只对敌人目标）。
- `state_effects.gd _active` 加两行认 `skipTypesAny`（共用判定处，所有确认阶段合成行都走这里）；原版数据没有这个键，别的状态不受影响。
- 开关 `XTianqiBase.HEAL_SKIP_ALLY`（默认 true；false＝照原来并进 `skipTypes`，我方回复照乘 ×5），O-待定，登记草稿见下。
- 走这条路的回复：只有 `XDamage.finish` 的确认阶段（全库唯一调用处）——技能／物品伤害类型 3（HP 回复）、4（MP 回复）。吸血（type 5／6）打敌人本来就跟去 ×6 走，不受影响；物品效果 11／12 的按比例回复、再生特性、谷雨储备等不经确认阶段，修前修后都不乘 ×5。
- 敌方：合成行只插给 `XActor` 持有者（`confirm_rows` 开头就判），敌人出手的确认阶段不变；我方打敌人伤害、混乱打自己人 ×6 照旧（专项断言 `hit_foe`、`hit_ally`）。
- 西游档（`XTianqiBase.on()` 假）`heal_skip_types()` 返回空，两个键都空，逐字节同原来。
