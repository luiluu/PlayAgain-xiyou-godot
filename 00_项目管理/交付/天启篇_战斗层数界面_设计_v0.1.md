## 一、推荐方案（甲：就近常驻）

一句话：**谁身上的层数，就画在谁的名字旁边，不进轮换；详情并进已有的面板。**

| 层数挂在 | 平时在哪看 | 点开看详情 |
| --- | --- | --- |
| 自己（砝码、换系、杀敌、段数、星数、集页、蓄势、免死、震印计数；渡鸦、饿狼、白起等） | 右侧状态行底边「层数条」，常驻 | 点层数条 → 现有状态详情（`XPartyStatusPanel`），层数作为卡片列进去 |
| 普通敌人（疫、流萤印记） | 选敌时名字窗里，轮换图标右边固定一排 | 不另开（v0.1）；说明写在装备说明里 |
| 首领 | 同上（选敌时）＋首领折叠栏预览 | 首领面板详情，层数作为条目列进去 |
| 全场（里副本规则、书卷规则） | 顶部「规则条」，常驻 | 点规则条 → 规则卡 |

### 2. 自己身上的：状态行「层数条」

状态行 121 高，TP 行画到 y94，**y96～120 一直空着**。层数条就画在这里，常驻，不轮换。

```
 行内 x: −36  0  12                                     200
 y 0          ┌──────────────────────────────────────────┐
   20 ┌────┐  │ 悟空                         储备        │ y6
      │状态│  │  HP ▓▓▓▓▓▓▓▓▓▓▓      999/999            │ y28
      │ 格 │  │   MP ▓▓▓▓▓▓▓          50/80             │ y50
   56 └────┘  │    TP ▓▓▓▓              120              │ y72
              │ [▣]5 [▣]2 [▣]3 [▣]  [▣]              +2  │ y96–120 ← 新
  121         └──────────────────────────────────────────┘
               砝码 换系 杀敌 蓄势 免死(灰＝未用)
```

| 项 | 取值 |
| --- | --- |
| 图标 | 23×23（32 缩到 23，和首领折叠栏预览同尺寸），y97 |
| 间距 | 每格 26（图 23＋空 3），从行内 x12 起，一排最多 7 格；多出来最后一格写「+N」 |
| 数字 | 层数，12 号，右下角压在图上，黑描边（同状态格层数画法） |
| 顺序 | 套装 → 武器 → 角色模块；同来源按接口 `order` |
| 没有层数 | 什么都不画（行看起来和现在一样） |
| 关掉开关 | 不画 |

各种「形状」怎么画：

| 形状 | 例子 | 画法 |
| --- | --- | --- |
| 层数 `stack` | 砝码 3／5、换系、杀敌 | 图标＋层数；0 层不画 |
| 一轮计数 `cycle` | 段数 7／10、星数 2／3、震印 2／3、集页 | 图标＋当前数；到「下一次触发」时按「满了」变色 |
| 有／无 `toggle` | 蓄势 | 有就画图标，不写数字；没有就不画 |
| 回合 `timed` | 免死后加伤 2 回合 | 图标＋剩余回合数 |
| 备用 `armed` | 灰印免死（每场 1 次，还没用） | 图标半透明（不写数字）；触发后换成「回合」画法；用完不画 |
| 文字 `label` | 里德六道轮盘（「天」「人」…） | 图标＋1 个字代替数字 |

为什么不进轮换：自己的层数是**每回合都要看**的（「砝码够不够 5 层、这回合放不放大招」）。进轮换要等最多 1.4 秒×格数；角色身上已有 5～8 个状态时一圈要 10 秒上下。底边那条本来就空，常驻不占新地方。

### 3. 敌人身上的：选敌名字窗固定显示

选敌时名字窗里现在是「名字＋一个轮换图标」。层数**不进轮换**，在轮换图标右边固定排：

```
           ┌────────────────── 名字窗 640×72 ──────────────────┐
           │            小妖  [轮换▣]  [▣ 2]  [▣ 7]   +1        │
           │                          疫  印记                  │
           └───────────────────────────────────────────────────┘
                            每格 32×32：右上 16 号＝剩余回合；左下 12 号「N层」#ffffa0
```

| 项 | 取值 |
| --- | --- |
| 位置 | 轮换图标右边空 6，往右每格 35（图 32＋空 3）；最多 3 格，再多写「+N」 |
| 画法 | **照抄现有选敌图标的写法**：回合数右上 16 号，「N层」左下 12 号 #ffffa0。玩家已经认得 |
| 不透明度 | 跟名字窗（淡入淡出一起走） |
| 首领 | 同上；另外 `XBossStatus.entries` 把层数行排在同类最前，折叠栏两格预览先看到「疫 3层 · 2回合」 |

### 4. 提示：只用「变色」＋「闪一下」

不用飘字（和伤害数字、回复数字挤在一起，看不清）。

| 情况 | 判定（界面自己比，模块不用管） | 提示 |
| --- | --- | --- |
| 满了／下一击会触发 | `value ≥ max` 或接口给 `ready` | 数字变金 #ffd773，图标描 1 像素金边，一直保持 |
| 快到期 | `turns == 1` | 回合数变红 #ff8f86 |
| 刚触发 | 接口的 `fired` 比上一次快照大 | 这一格白光闪一下：0.5 秒内由 60% 白降到 0 |
| 刚到上限 | `value` 从未满变满 | 同「刚触发」闪一下，然后保持金色 |

例：黑印 5 件，砝码到 5 层 → 金色；放伤害技能一次用掉 5 层必暴 → `fired`＋1，砝码格闪白，然后层数归零不画。

### 5. 详情说明怎么写

格式统一三段：**名字 · 现在几层／上限 · 剩余回合** ／ 一句规则（带现在的数） ／ 来源。

| 条目 | 卡片标题行 | 说明 | 来源行 |
| --- | --- | --- | --- |
| 疫（敌人身上） | 疫 · 3层／10 · 剩 2回合 | 每回合受到攻击者物攻 10%×层数的伤害（现在 30%）。白印武器每命中一次叠 1 层，叠层时回合数刷新为 3。 | 白印武器 |
| 砝码（自己身上） | 砝码 · 3层／5 | 每回合开始得 1 层，上回合防御再得 2 层。放伤害技能时全部用掉，每层伤害 +15%（现在 +45%）。一次用掉 5 层时必定暴击。 | 黑印套装 5 件 |
| 杀声（规则） | 杀声 · 里副本规则 · 全场 | 每有一个单位倒下，全场出伤 +5%（本场已倒下 2 个，现在 +10%）。 | 红印里副本 |
| 杀声（书卷揭的） | 杀声 · 七印书卷 · 只对敌方 | 每有一个单位倒下，打在敌人身上的伤害 +5%（现在 +10%）。 | 七印书卷 |

规则文字直接用 `qiyin_altar.json` 的 `rule_text`；括号里的「现在」由模块拼。说明以代码为准，界面不自己编数。

## 二、其他方案和为什么不选

| 方案 | 做法 | 好处 | 为什么不选 |
| --- | --- | --- | --- |
| 乙：伪状态进轮换 | 层数当成状态行塞进状态格轮换和选敌轮换（图标＋右下层数） | 改动最小，详情面板天然就有 | 「我现在几层砝码」最多要等 1.4 秒×格数；状态多时一圈 10 秒；满了闪一下可能刚好轮不到，看不见 |
| 丙：独立层数面板 | 计量条下面另开一块列表，按角色分组列全部层数 | 一眼看全 | 离角色远，要对名字；和 Boss 血条框、首领折叠栏、天启计量条都在左上，挤；安卓上更挤 |
| 丁：敌人脚下常驻 | 每个敌人脚下画一排小标 | 不用选敌也知道谁有疫 | 敌人位置不固定、会重叠；5～8 只时满屏小数字；留作 Kyo 第 2 问的备选 |

甲吸收乙的长处：层数行**也**列进状态详情和首领面板，所以「点开看全部」和乙一样。

## 四、数据接口（给程序）

### 总体

```
各模块（XTianqiQiyinEffects、XTianqiQiyinRule、渡鸦、饿狼……）
        │ 只读、纯函数：battle_stacks(logic, b) / battle_rules(logic)
        ▼
XBattleStacks（新，modes/xiyou/battle/battle_stacks.gd，只汇总）
        │ of(logic, b) → 排好序的条目；rules(logic) → 规则条目
        ▼
battle_logic.view_of 快照里多一个 "stacks"（和 cell_rows 一样跟演出同步）
        ▼
XSideStatus（层数条）、XEnemyStateIcon（名字窗）、XBossStatus.entries、XPartyStatusPanel、规则条
```

### 模块要提供的两个静态函数

| 函数 | 谁实现 | 返回 |
| --- | --- | --- |
| `static func battle_stacks(logic, b) -> Array` | 每个有层数的模块 | 这个战斗者身上的层数条目（下表），没有返回 `[]` |
| `static func battle_rules(logic) -> Array` | `XTianqiQiyinRule`（以后别的全场规则也走这里） | 本场规则条目 |

`XBattleStacks` 照 `XTianqiMeter.module()` 的办法按类名动态取模块（模块不在这个分支也能编译）。模块名单写成一张常量表：

```
const PROVIDERS := ["XTianqiQiyinEffects", "XTianqiQiyinRule", "XRavenEcho", "XWolfEvolve", …]
```

### 层数条目字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `key` | String | 是 | 全局唯一，如 `qiyin.weight`、`qiyin.plague`；界面用它记上一次的值 |
| `icon` | int | 是 | 图标号（310601 等）；0＝没图，用名字第一个字顶上 |
| `name` | String | 是 | 2～3 字，如「砝码」 |
| `shape` | String | 是 | `stack` / `cycle` / `toggle` / `timed` / `armed` / `label`（见一.2） |
| `value` | int | 是 | 当前层数／计数；`toggle` 有＝1 |
| `max` | int | 否 | 上限；0＝没有上限 |
| `turns` | int | 否 | 剩余回合；−1＝没有 |
| `label` | String | 否 | `shape=label` 时显示的 1 个字 |
| `ready` | bool | 否 | 下一次行动会触发（段数满一轮、星数满、震印 3／3、砝码 5 层且 5 件） |
| `fired` | int | 否 | 本场已触发几次，只增不减；界面看它变大就闪 |
| `kind` | String | 是 | `增益` / `异常`（详情面板、首领面板分类用） |
| `text` | String | 是 | 一句规则，括号里带现在的数（见一.5） |
| `source` | String | 是 | 「黑印套装 5 件」「白印武器」「渡鸦」 |
| `order` | int | 否 | 同来源内的顺序 |

### 规则条目字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `key` | String | `no_cure` 等，和 `qiyin_altar.json` 的 `rule` 一样 |
| `icon` | int | 310500＋规则序 |
| `name`、`text` | String | `rule_name`、`rule_text` |
| `scope` | String | `all` 全场 / `enemy` 只对敌方（书卷） |
| `source` | String | 「白印里副本」「七首之龙」「七印书卷」 |
| `count` | String | 规则条右下的小数字，空＝不画 |
| `lit` | bool | 现在正在起作用（寂静的双数回合） |

### 谁调、什么时候刷新

| 时机 | 做什么 |
| --- | --- |
| `battle_logic.view_of(b)` 拍快照时 | 顺手调 `XBattleStacks.of(logic, b)`，放进快照 `stacks`；演出中界面只读快照，和伤害数字同步 |
| 等指令（`_refresh_status`、`clear_views` 之后） | 界面读实时值 |
| 规则条 | 每回合开始、每次行动结束各拉一次 `rules(logic)` |
| 每帧 | **不拉数据**；只在有格子在闪时重画 |

不用信号、不用每帧轮询：模块是纯读，拍快照时顺带拉一次就够了。

### 战斗结束怎么清

- 模块自己的本场数据照旧在战斗结束清（现在就是）。
- `XBattleStacks` 不存状态；界面记「上一次的 value／fired」的字典放在 `XBattleScene` 实例上，场景释放就没了。
- 新开一场，第一次快照不闪（没有上一次的值就只记不闪）。

### 开关

- `XBattleStacks.ENABLED := true`（static var，同项目回退开关写法）。
- `XBattleStacks.on(logic)` = `ENABLED and XTianqiCombat.on()`；为假时 `of()`、`rules()` 都返回 `[]`，所有界面走现在的分支（层数条、名字窗固定格、规则条都不画；面板不多行）。

## 六、安卓与小屏

### 触屏没有悬停

| 东西 | 桌面 | 触屏 |
| --- | --- | --- |
| 自己的层数条 | 悬停写「名字：层数说明」；点 → 状态详情 | 点状态行下半（y70～121，x0～200，比层数条大，好点） → 状态详情，打开时滚到层数卡 |
| 状态格 | 不变 | 不变 |
| 选敌名字窗层数 | 只看 | 只看；首领的点首领折叠栏 |
| 规则条 | 悬停写规则；点 → 规则卡 | 点 → 规则卡；点卡外关 |
| 选目标中 | 层数条不响应点击（免得误点） | 同左 |

- 点开状态详情照现在的规矩：只在等指令时能开（演出中开不了）。
- 不用长按（安卓上和拖动、系统手势容易打架）。

### 字号与尺寸

画面按 720 高等比缩放。常见手机（2400×1080）放大 1.5 倍；最小按 1600×720（不放大）算：

| 东西 | 设计尺寸 | 最小可接受 |
| --- | --- | --- |
| 层数数字 | 12 号，黑描边 | 12 号（和原版状态格层数一样；1.5 倍时实际 18 像素） |
| 规则卡、详情说明 | 16 号 | 13 号 |
| 小图标 | 23×23 | 不再缩；放不下就「+N」 |
| 可点区域 | 至少 36×36 | 层数条点区 200×51、规则条 38 高，都够 |

### 小屏挤的时候

- 层数条一排最多 7 格，再多「+N」（点开详情看全部）。
- 规则条七条只画图标不写字（250 宽），不和 Boss 血条框（右边到 612）、状态格（最左到 996）撞。
