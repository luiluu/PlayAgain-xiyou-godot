## 根因（定位到那一行）

**不是工具代码互杀，是车道会话手动跑了按名字的 `pkill`。** 07_开发环境 里没有任何 pkill／killall／按名字或端口清 Godot 的代码（长任务.py 只给自己状态里登记过身份的进程组发信号，launchd 清扫只卸已结束的作业）。系统日志＋各会话记录对上了 11-16 全部三次本机检查 143：

| 时间（UTC，本地 +1） | 被杀的检查 | 谁、跑了哪一行 |
| --- | --- | --- |
| 09:05:50 | text-batch23 检查 | text-batch23 车道：`pkill -f "检查.sh --affected main"; pkill -f "并行测试.py"; …; pkill -f 07_开发环境/godot` |
| 18:06:30（19:06） | cc-tianqi-again-use 检查等 3 个 launchd 作业同一刻退出 | cc-dexiyou-names 车道：`pkill -f 检查.sh; pkill -f 并行测试.py; sleep 3; pkill -f "Godot"` |
| 21:24:28（22:24） | cc-mount-drop-fix ×2、cc-raven-again-use、cc-battle-ui-v07 共 4 个同一刻 143 | cc-ui-polish-1116 车道：`pkill -f "检查.sh --affected" ; pkill -f "并行测试.py"` |

- 机理：`pkill -f` 按整条命令行匹配；每条车道的检查（zsh 检查.sh）和它的包装器（`python3 长任务.py run … -- …/检查.sh --affected …`）命令行里都有 `检查.sh --affected`，全机一起收到 SIGTERM；包装器的处理函数停掉自己的进程组、写终态 143。launchd 日志是「exited due to exit(143)」（包装器自己退出），随后的 bootout 是各车道的 `等待任务.sh` 正常收尾，不是凶手。
- 「正好是别的车道起检查的同一秒」：那条车道是在**重起自己的检查之前**先 pkill 清场，所以看起来像「别人一起检查，我就被杀」。T099 尾段被掐我没逐条核对时间，多半是同一类。

## 修法

1. `长任务.py stop <日志>`／新 `停止任务.sh`：只停核实过身份的自己那一轮（先 SIGTERM 包装器让它停整组、写终态；包装器不在才直接停登记的任务进程组；身份对不上不发信号）。不给日志＝停当前工作树登记在跑的全部任务；`长任务.py list [--all]` 列在跑的任务。登记在 `~/.cache/xiyou_longtasks/`（`XIYOU_LONG_TASK_REGISTRY` 可改），结束即删。
2. 外来 SIGTERM 留痕：包装器（或任务进程直接）收到 SIGTERM、而没有本轮 `<日志>.stop` 请求时，终态 `reason` 记「收到外来 SIGTERM（…多半是别处跑了按名字的 pkill／killall）」；自己 stop 的记「已由 长任务.py stop 主动停止」。以后再出 143 不用翻系统日志。
3. 检查.sh 开头打一行「要停这轮检查只用：python3 …/长任务.py stop <本轮日志>（别 pkill／killall 检查.sh、并行测试.py、godot）」，车道复制即可。
4. `守卫_按名杀进程.py`：Claude Code PreToolUse 钩子脚本，拦下没写本工作树路径的 `pkill／killall`（目标涉及 检查.sh、并行测试、长任务、云端选测、占槽、godot、node、python），提示改用 停止任务.sh。**只写了脚本和回归，没注册**（见「需要决定」）。
5. 进程组本来就对：并行测试.py 起的 Godot 不另开会话，留在检查的进程组里，所以按组停能连带收掉 Godot，不用按名字清残留。
