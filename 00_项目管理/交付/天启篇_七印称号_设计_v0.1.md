## 顺带发现（不改，先告知）

- **主菜单、装备页角色栏右列那一格不是 Star 称号。** `paint_actor_status` 画的是角色的 `nickname`（没有就画职业名），和 `XState.designation` 无关。Star 称号现在**只**画在头顶名牌上。
- 本档佩戴只存 `{name, icon, color}` 三项快照，不存编号。所以关掉开关时没法认出「这是天启篇的称号」，下面方案要补一个 `id`。
- 原版表里 10、11 号同名（都叫「魔塔之主」），原版如此，不动。

## 一、称号卡

### 名字候选

七套名字都出自启示录第 6～8 章（胜了又要胜、夺去太平、天平与一钱、阴府随着、要等到几时、天如书卷、寂静约有二刻）。称号接着这条线走：揭完七印之后的那一句。

| 候选 | 出处 | 味道 | 评价 |
| --- | --- | --- | --- |
| **甲 配揭七印**（推荐） | 5:9「你配拿书卷，配揭开七印」 | 天上给的头衔，也是罪名：末日是你亲手揭开的 | 四字，和「胜而又胜」「斤斤计较」同节奏；名牌一行放得下 |
| 乙 七号已备 | 8:6「拿着七枝号的七位天使就预备要吹」 | 揭完印，号角才要开始 | 宿命感强，但要读过原文才懂，单看像「七号」编号 |
| 丙 谁配揭印 | 5:2「有谁配展开那书卷，揭开那七印呢」 | 反问，像「要到几时」 | 讽刺最足，但戴在头上像在问自己 |

### 颜色、图标、名牌

| 项 | 定法 |
| --- | --- |
| 名字颜色 | **#E0B95A**（默印副色，书卷金）。七色不进名字：名牌只有一种字色，七色放进图标里 |
| 为什么不用红 | #E0262B 是真印的红光，名字用红会被读成「真印称号」 |
| 图标 | 32×32 像素，透明底。一圈七片碎开的封蜡（按七印主色，顺序同揭印：白 红 黑 灰 殉 震 默，12 点钟起顺时针），圈中是展开的空白书卷、透一点金光。圆形轮廓，和骑士徽记的八角框区分；和神器「七印书卷」（封蜡完整、卷着）区分 |
| 图标号 | `XTianqiQiyinArt.SMALL` 加一块 900：`["title_qiyin_all"]`，`ICON_END` 900→1000。号 **310900**；文件 `icons/title_qiyin_all.png` |
| 名牌 | 照现有排版，不加特效（原版 30 条都没有）：图标居中在上（x74 y0），「配揭七印」#E0B95A 粗体黑描边在中，开局名字白字在下 |
| 数值 | 无 |

名牌示意（180×78）：

```
        [七片碎封蜡＋书卷 32×32]
            配揭七印        ← #E0B95A
             悟空           ← 白
```

## 二、解锁与补记

**条件**：七印外观全部解锁＝全局配置 `codexTianqiQiyinParts` 里七印 × 六部位都有记录。称号判定直接读这个键，不另记部位，只有一份账。

### 什么时候查

| 时机 | 做什么 | 提示 |
| --- | --- | --- |
| 揭开一件七印装备（回祭坛揭、结算当场揭） | 外观记下部位；若这下凑齐了第七印的外观，接着查称号 | 有，见下 |
| 开祭坛 | 外观先把本档印库补记一遍（已有做法），补完查一次 | 有，只说一次 |
| 打开称号选单 | 静默查一次，兜底 | 选单顶上一行「新得到：配揭七印」 |
| 读档、开游戏 | **不查** | — |

读档不查的理由：读档时在标题或地图上弹提示，位置不对；有祭坛和选单两处兜底就够。

### 老进度怎么补

- 外观功能上线前揭过的部位，靠外观的「开祭坛时把本档印库补记一遍」补进 `codexTianqiQiyinParts`；称号不另外补，补完那一下查就行。
- 已经集齐七印外观的老进度：第一次开祭坛（或第一次开称号选单）就给，不用重刷。
- 别的存档里揭过、但这个档印库里没有的部位，补不回来（外观也一样）。不为此加别的补法。

### 集齐那一刻

| 项 | 定法 |
| --- | --- |
| 台词 | 接在第七印外观那句话后面，一句：「七印都揭开了。书卷上再没有封着的地方。」换行「得到称号 \I[310900]配揭七印」 |
| 演出 | 祭坛的七盏印灯按揭印顺序依次亮一下（每盏约 0.1 秒，总共不到 1 秒），配一声原版已有的提示音。不切画面、不黑屏 |
| 戴不戴 | 台词后给一个选项「现在戴上／先不戴」。选「戴上」直接写进本档佩戴 |
| 结算当场揭时凑齐 | 同一句话出在结算窗口里，灯不闪（结算窗口没有印灯） |
| 只说一次 | 解锁写进配置的那一下才说；之后再查到已解锁就不说 |

## 三、称号表号段与并存

| 项 | 定法 | 理由 |
| --- | --- | --- |
| 号段 | 天启篇称号 **301～399**，跳过带 4 的号（第一个是 301） | 插件参数只到 Designation 100，原版以后更新也撞不上 |
| 表从哪来 | 新数据表 `tianqi_data/titles.json`（只读），原版表照旧读插件参数，不改原版数据 | 两张表各管各 |
| 解锁记在哪 | 新全局键 **`codexTianqiTitles`**（数组，存称号键如 `"qiyin_all"`），不写进 `DesignationN` | 和 `codexTianqiBadges`、`codexTianqiAliens` 同一写法；`DesignationN` 保持只有原版的号 |
| 本档佩戴 | 照旧写 `XState.designation`，**加一项 `id`**（天启篇称号写 301 等；原版称号也顺手写上编号）。读老档没有 `id` 不出错 | 关开关时要靠它认出天启篇称号 |
| 排序 | `XDesignation.table()` 先原版 1～30、再 31 kyo 专属、最后天启篇 301 起 | 原版选项下标不变 |

### 原版档看不看得到（Q2）

| 方案 | 好处 | 坏处 |
| --- | --- | --- |
| **只在天启篇档出现**（推荐） | 原版档的选单和原版逐项一致，`designation_oracle.json` 的选单用例（31 项）不用改；天启篇本来只在 Kyo 本地 | 原版档里看不到自己拿过的天启篇称号 |
| 出现但标「天启篇」 | 一处能看全 | 原版档选单多出项，对照测试要分支；原版档也能戴上天启篇称号，跨了「天启篇只在天启篇里」的边界 |

判断「天启篇档」用现成的 `XTianqi.active(s)`。

### 开关（可回退）

| 开关 | 关掉后 |
| --- | --- |
| `XTianqiTitles.ENABLED = false` | 选单不列天启篇称号；不再查、不再解锁；祭坛不说称号那句话 |
| 已解锁记录 | **留着不删**（`codexTianqiTitles` 不动），开回来照旧 |
| 本档正戴着的天启篇称号 | 存档里不删；名牌按 `id` 认出来后不画（当作没戴）。开回来又画出来 |
| 称号页（完整方案） | 天启篇档也回到原版选项窗 |

## 四、称号功能补完

### 最小方案（只够挂上七印称号）

| 项 | 做法 |
| --- | --- |
| 数据 | `titles.json` 一条：`qiyin_all`，按完整方案的格式写（键、号、名、图标、颜色、分组、条件、提示） |

| 入口 | 方桌大厅「更换称号」照旧；**七印祭坛菜单加一行「称号」**，打开同一个选项窗 |
| 解锁提示 | 第二节那句话＋「现在戴上」选项 |
| 两层存储 | 不改结构：全局解锁＋本档佩戴；只加 `codexTianqiTitles` 键和佩戴的 `id` |
| 要动的文件 | `designation.gd`（table 接天启篇、apply 写 id）、`designation_plate.gd`（开关关时不画）、`xstate.gd`（存读 id）、`xconfig.gd`（新键）、`tianqi_qiyin.gd`（祭坛菜单一行、补记后查）、外观类（凑齐时查）、`tianqi_qiyin_art.gd`（图标块 900）、新 `tianqi_titles.gd`＋`titles.json` |

### 完整方案（骑士徽记、七首之龙、神器都能挂）

| 项 | 做法 |
| --- | --- |
| 称号页 | 天启篇档换成一个新页（原版档照旧选项窗，对照测试不动）。左列分组列表，右边详情 |
| 分组 | 原版／天启篇·七印／天启篇·骑士／天启篇·七首之龙／天启篇·神器。空组不显示 |
| 详情 | 名牌预览（直接用 XDesignationPlate 画）、解锁条件、进度（七印称号画七盏小印灯，亮几盏是几盏）、来源 |
| 没解锁的显示 | 天启篇称号：**名字和条件都显示**（是追求目标）；标了「隐藏」的只写「？？？」和一句提示。原版称号：照旧 `???`、不写条件（原版没给条件，不编） |
| 按钮 | 戴上／摘下／返回 |
| 入口 | 方桌大厅「更换称号」（天启篇档开新页）、七印祭坛菜单「称号」。**主菜单不加**：19 条指令和原版逐像素对，不动 |
| 条件 | `titles.json` 每条写条件类型＋参数；`XTianqiTitles` 按类型判（七印外观全齐、徽记全亮、七首全断……），加称号只加表和一个判定函数 |
| 查的时机 | 各来源在「记下新进度」那一下调 `XTianqiTitles.sync()`；开称号页静默兜底一次 |
| 两层存储 | 不改：全局解锁（`codexTianqiTitles`）＋本档佩戴（`designation`＋`id`） |

### 两案对比

| | 最小 | 完整 |
| --- | --- | --- |
| 够不够挂七印称号 | 够 | 够 |
| 天启篇称号到 3 个以上 | 选单里一排 ???，看不出要干什么 | 分组＋条件 |
| 动原版画面 | 不动 | 只在天启篇档 |

## 六、美术需求（给 GPT 生图用，可直接贴）
