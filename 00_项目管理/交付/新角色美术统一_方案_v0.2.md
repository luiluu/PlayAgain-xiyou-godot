## 一、要 Kyo 定的问题（5 个）

| # | 问题 | 推荐 | 理由 |
| --- | --- | --- | --- |
| Q1 | 头像走**赛璐璐**还是**像素**？ | **赛璐璐**（透明底、平涂＋一层硬阴影） | 原版 166 人的头像都是赛璐璐，对话框、图鉴、队伍里天天和新角色混排；像素头像 144 格实际只有 72 点（五条悟就是 2 倍放大），表情细节少，和原版放一起反而更扎眼。五条悟头像不在这 13 人里，建议顺带补一版赛璐璐，开关回退。 |
| Q2 | 第一批四人（云裳、屠苏、璇、流萤）以外的 9 人（渡鸦、米拉、黄泉、镜流、甚尔、宿傩、饿狼、谷雨、哈基米），行走图和战斗图也按五条悟 v2 重画吗？ | **重画**，放第三批 | 五条悟 v2 比旧的标准像素图精细一档（冷色阴影、轮廓光、表情清楚）；不重画的话新旧两档并排还是不齐。用参考重绘法每人只要 4 张母图（战斗 3＋行走 1），成本低。变身逐帧大图（米拉黑龙、渡鸦神话、宿傩完全体、饿狼星空）照旧不重画，只做像素化。 |

| Q5 | 战斗精灵新做法先做哪条？ | 人形角色一律走**参考重绘法**（五条悟 v2 的做法）；**离线像素化脚本**只给变身大图和屠苏璇绑定形态用；纸娃娃**暂不做** | 参考重绘法已经在五条悟上出了定稿，每人 4 张母图就够，动作和原图一一对应；纸娃娃要先做工具和共用身体，还有生成器素材授权问题，收益被参考重绘法盖过了。详见第六节。 |

**出图方法（照 `母图/出图记录.md`）**：拿现有的行走图、战斗图当姿势和站位参考，另给一张配色参考，让 GPT 逐格重绘。战斗图分 3 张母图（每张 6 列×3 行，两个动作并排），行走图 1 张（3×4）；再降到 48／64 格，按旧帧的可见底边对齐。第四节的模板就照这个改。

**提示词注意**：五条悟的母图提示词写了角色名和作品里的制服名。其余 13 人照 Kyo 之前的要求，只写外观特征，不写角色名和作品名（第四节已经这样写）。

## 四、GPT 生图提示词

### 4.0 总原则

- GPT 出不了严格像素网格。**一律出大图当「母图」，再用脚本降到游戏尺寸**。不让 GPT 直接出 48、64、32 的图。
- **行走图、战斗图用参考重绘法**（五条悟 v2 定稿的做法，见 2.4）：把这个人**现有的图**当第一张参考（姿势、朝向、站位、帧序都照它），把五条悟 v2 母图当第二张参考（只取画法、明暗、配色克制度），让 GPT 逐格重绘。每格动作和旧图一一对应，帧序不会错。
- 母图分法照五条悟：行走 1 张（3 列×4 行）；战斗 3 张（每张 6 列×3 行，两个动作并排，按 MV 18 动作的顺序切成三段）。**每人 4 张母图**。
- 参考图要先整理：高清旧图（云裳 192 格、流萤和哈基米 128 格）先缩到 64 格再拼成 6×3 参考；屠苏、璇 96 格行走图缩到 48 格；屠苏、璇的战斗图人物太小，先放大到站姿高 59 再拼参考。
- 每个人再给一张**头像**当外观参考（第三张参考图），保证发型、衣服、配色对得上。
- 外貌只写特征，不写角色名和作品名。
- 背景写 `transparent background`；GPT 偶尔给棋盘格假透明，后处理第一步按 alpha 检查，不对就按纯色底抠。

### 4.1 模板

**A. 头像（赛璐璐）**

```

Body turned slightly to the viewer's left, eyes toward the viewer.
Clean dark line art (2-3 px at this size), flat colors with exactly one hard-edged shadow tone,
one small highlight on hair and eyes only. No gradients, no painterly texture, no glow, no particles.
Light from the upper left. Fully transparent background, nothing behind the character.
Head top near the upper edge, shoulders cut by the bottom edge, character centered.
1024x1024 PNG, single character, no text, no frame.
```

**B. 参考重绘的共用前段（行走、战斗都先接这一段）**

改写自五条悟 `出图记录.md`，把角色名、作品名换成外观特征：

Transparent RGBA all around every silhouette, including gaps between limbs. The sprite art should work on dark backgrounds.
Keep distinct unchanged baselines and relative offsets within each cell, including crouched or fallen poses.

`[WEAPON RULE]`：武器由游戏的 `Sprite_Weapon` 另画的人写 `No weapons.`；武器画在身上的人（黄泉的刀、镜流的剑、哈基米的剑、流萤的光刃、甚尔的咒灵）写 `Keep the [weapon] exactly as in the reference, drawn once.`

### 4.3 出图后到游戏规格的统一流水线

按顺序，一个脚本跑完（建议放 `03_再刷重制_Godot/07_开发环境/美术统一/`，只有脚本进仓库，图不进）：

1. **检查透明**：alpha 全 255 → 按四角颜色抠底；有棋盘格 → 报错重出。
2. **切格**：母图按格子等分；每格里找人物外接框（alpha ≥ 128），框跨格或一格两个人 → 报错重出。
3. **定目标大小**（以五条悟 v2 为准）：行走站姿高 45～46、宽约 32；战斗站姿可见高 59～60；低姿势按母图里和站姿的比例同比缩（不各自拉满）；技能符号 24；装备 26；头像不走这条。同一张母图所有格用**同一个缩放比**（按站姿格算），不逐格缩。
4. **盒式缩小**（先缩到目标的 4 倍，再 4×4 取均值；比直接 Lanczos 少振铃）。
5. **对齐**：每格按**旧图同一格的可见底边**对齐（五条悟 v2 的做法），水平按旧图可见中线对齐；旧图不可用的（屠苏、璇太小）按 v2 同动作的格对齐。
6. **alpha 二值化**：≥128 → 255，其余 0（五条悟 v2 没做这步，外缘留了一圈半透明暗边）。
7. **不硬量化**：五条悟 v2 每帧约 1300 色是正常的；压到 48 色时蓝眼睛被并成灰。只在色数明显过多（每帧 >2500）或有杂色点时，用「保护色」量化（眼睛、饰物等小面积亮色先放进色板）。
8. **去孤点**：和四邻都不同、且四邻颜色一致的单点改成邻色（清掉 GPT 的噪点；旧版五条悟的绿点就是这类）。
9. **描边只补不改**：GPT 已经画了选择性描边的不动；外缘有缺口（透明直接贴亮色）的点才补 1px，颜色取该处固有色压暗。
10. **拼图**：行走按 3×4 摆进 144×192；战斗按 4.1 D 的位置摆进 9×6、576×384；图标按号段摆进 32 格图集。
11. **出预览**：原大＋4 倍最近邻各一张，和五条悟 v2、原版同类图并排（绿司机、原版 IconSet 一行），再出新旧对照动图（同五条悟审样包），给 Kyo 逐帧看（总说明 §5.5 的检查照旧要人看）。

## 六、战斗精灵新做法评估

> v0.2：五条悟 v2 用「参考重绘法」出了定稿，它比下面 A、B 两条都直接。所以人形角色的行走图和战斗图**主路是参考重绘法**（第四节 B～D），A 只留给变身大图和绑定形态，B 降为备用。A、B 的评估原文保留，供以后参考。

### A. 像素化着色器

**做法比较**

| 方式 | 怎么做 | 评价 |
| --- | --- | --- |
| A1 CanvasItem 着色器（挂在身体 Sprite2D） | 片元里把 UV 吸附到 N×N 像素块中心；块内用 4 点采样取平均；alpha 二值化；在调色板贴图里找最近色；块透明而四邻有不透明块 → 画描边色 | 不用离屏，跟现有 `BODY_SHADER`（色相、闪光、裂隙）可以合成一个；每帧算 |
| A2 SubViewport | 我方精灵先画进低分辨率视口，视口贴回来时最近邻放大，再套 A1 的量化描边 | 武器、特效能一起像素化，但站位、浮空、翻转、光标、伤害数字都要重算坐标，改动面大 |
| A3 离线脚本（推荐） | 同一套算法用 Python 跑一次，出 `_u1` 文件，走 5.2 的开关 | 零运行时开销；产物能逐张审、能手修；和第四节流水线是同一个脚本 |

**参数**

| 参数 | 建议值 | 说明 |
| --- | --- | --- |
| 块大小（缩放倍率） | 源图可见高 ÷ 56，取整 | 云裳 192 格可见高 132 → 块约 2.4，按 2 或 3 试；流萤可见高 116 → 2 |
| 调色板来源 | 每人一张 1×N 贴图，离线从站姿帧中位切分出 32 色 | 不要全局一张板，肤色、发色会串 |
| 描边宽度 | 1 块 | 颜色：块固有色压暗到亮度 8% |
| alpha 阈值 | 0.5 | |
| 跳过名单 | 已经是 48／64 像素格的角色、原版 1～166 号、敌人 | 开关只按图名白名单生效，不按角色 ID 猜 |

**A1 着色器骨架（示意，不是成品）**

```glsl
shader_type canvas_item;
uniform vec4 region;            // 这一帧在图集里的 x, y, w, h（像素）
uniform float block = 2.0;      // 像素块边长（源图像素）
uniform sampler2D palette : filter_nearest;
uniform int palette_size = 32;
uniform float outline_dark = 0.08;
vec4 sample_block(vec2 px, vec2 ts) {      // 4 点平均
	vec4 c = vec4(0.0);
	for (int i = 0; i < 2; i++) for (int j = 0; j < 2; j++)
		c += texture(TEXTURE, (px + (vec2(float(i), float(j)) + 0.5) * block * 0.5) / ts);
	return c * 0.25;
}
void fragment() {
	vec2 ts = vec2(textureSize(TEXTURE, 0));
	vec2 local = UV * ts - region.xy;
	vec2 cell = floor(local / block) * block + region.xy;
	vec4 c = sample_block(cell, ts);
	if (c.a < 0.5) {   // 描边：四邻块有不透明就画暗色
		float n = sample_block(cell + vec2(block, 0), ts).a + sample_block(cell - vec2(block, 0), ts).a
			+ sample_block(cell + vec2(0, block), ts).a + sample_block(cell - vec2(0, block), ts).a;
		COLOR = n > 0.5 ? vec4(vec3(outline_dark), 1.0) : vec4(0.0);
	} else {
		vec3 best = c.rgb; float d0 = 9.0;
		for (int i = 0; i < palette_size; i++) {
			vec3 p = texelFetch(palette, ivec2(i, 0), 0).rgb;
			float d = distance(p, c.rgb);
			if (d < d0) { d0 = d; best = p; }
		}
		COLOR = vec4(best, 1.0) * COLOR;
	}
}
```

**性能（安卓）**：我方最多 5 人，每人屏上约 72×129 像素，一个像素 20 次采样＋32 次比色，全场不到 100 万次运算，中低端安卓 GPU 也无感。真正的成本是 `region` 每帧要从 `_show_frame()` 传进去，和 `BODY_SHADER` 合并时要小心别打断现有的色相、闪光。

**哪些做不好、还得重画**

| 角色 | 像素化结果预期 | 结论 |
| --- | --- | --- |
| 云裳（192 格、Q 版插画） | 轮廓简单、色块大，块 2～3 能出可用的像素图 | **先试 A3**，不行再重画 |
| 哈基米（128 格） | 本来就是像素图只是格子大 | 不用着色器，工序①裁格 |
| 流萤（128 格动画风） | 大眼睛、柔光、发丝渐变，块 2 后脸部只剩 3～4 点高，表情糊 | **重画** |
| 屠苏、璇（64 格本体） | 源图只有 28×36，再像素化也补不出细节 | **重画** |
| 屠苏、璇绑定形态、附身（128／160） | 武器、光效为主，像素化后风格能对上 | **A3** |
| 变身逐帧图（黑龙、神话渡鸦、宿傩完全体、饿狼星空） | 体型大、动作多，像素化后能对上画风 | **A3**，尺寸不动 |

**结论 A**：做 **A3 离线脚本**，约 1～2 天（含预览页和开关），**只用于变身逐帧大图和屠苏璇绑定形态、附身图**（这些不重画）。云裳、流萤、屠苏、璇的本体改走参考重绘，不再靠像素化。A1 着色器作为调试开关可选做（约 1 天）；A2 不做。

### B. 纸娃娃拼装

**背景**：原版 MV 的人物本来就是 RPG Maker 生成器拼出来的（身体＋脸＋前后发＋衣服＋配件，每层都是完整的 54 格 SV、12 格行走、头像）。总说明 §5.1「路线二」、§7.1、§7.3 已经做过一个独立生成器和搭配页。所以纸娃娃不是新路，是**回到原版母本的做法**。

**图层划分**（照 MV 生成器层序，从下到上）

| 层 | 内容 | 每层规格 | 谁出 |
| --- | --- | --- | --- |
| L1 后发 | 头后面的头发 | SV 576×384、行走 144×192 | 新画（按头部锚点平移，见下） |
| L2 披风后 | 披风背面 | 同上 | 生成器部件改色 |
| L3 身体 | 共用身体（男、女、儿童三种） | 同上；18 动作全有 | 生成器原件，不画 |
| L4 衣服 | 上衣、下装 | 同上 | 生成器部件改色；特殊服装才画 |
| L5 脸 | 眼、眉、嘴 | 同上 | 生成器部件改色 |
| L6 前发 | 刘海 | 同上 | 新画（锚点平移） |
| L7 头饰／角／耳 | 角、发饰、猫耳 | 同上 | 新画（锚点平移） |
| L8 武器 | 手持武器 | 用原版 `Sprite_Weapon` 那套，不进纸娃娃 | 已有 |

**关键做法：头部锚点平移**。共用身体每一帧标一个头部锚点（54 个坐标，一次标完）。发型、头饰只画**一张**朝左的头部件，按锚点平移贴到 54 格。像素 Q 版的头基本只平移不旋转，这样一个发型从 54 张降到 1～3 张（站立、低头、倒地）。

**怎么出图**：GPT 只出静态正面＋侧面（v0.1 的设定图，v0.2 已删），人工按共用身体的头部轮廓抠出发型层，降到像素（第四节流水线）。动作完全靠共用身体。

**Godot 端怎么叠**

| 方式 | 说明 | 建议 |
| --- | --- | --- |
| 运行时多个 Sprite2D 同 region 叠 | 每层一个子节点，同步切帧 | 不做：`battler_sprite` 的着色器、闪光、浮空、翻转都要对每层重做 |
| 加载时合成一张 ImageTexture | 进战斗时按配置把层合成 576×384，缓存进 `XAppearance.kept_load` 的缓存 | 可做，但对固定外观没收益 |
| **离线合成（推荐）** | 工具里叠好直接出标准 576×384、144×192、576×288 | **做这个**：游戏端零改动，走 5.2 的开关 |
| 换色 | 层上留色罩（总说明 §7.1 已有），离线换 | 运行时换色只有将来做「时装染色」时才需要 |

**现有 13 人谁适合迁过去**

| 适合 | 不适合 |
| --- | --- |
| 屠苏、璇、流萤（都要重画 SV，人形、服装不复杂；用纸娃娃比 GPT 出 15 个关键姿势更稳、和原版骨架完全一致） | 哈基米（猫，无对应身体）、饿狼星空、米拉黑龙、渡鸦神话、宿傩四臂（体型特殊） |
| 云裳（A3 失败时的后备） | 已经是标准像素、保留的人（渡鸦、米拉、镜流、甚尔） |

**以后新角色的出图清单（纸娃娃路线）**

| 序 | 出什么 | 张数 |
| --- | --- | --- |
| 1 | GPT 设定图（正面＋侧面站姿） | 1～2 |

**授权提醒**：MV 生成器素材的授权一般限「用 RPG Maker 做的游戏」。Godot 重制版能不能用生成器原件做新角色，要 Kyo 确认；不能用的话，L3 共用身体要自己画一套（约 54 格＋12 格，一次性），其余流程不变。

**结论 B**（v0.2 改）：**暂不做**。参考重绘法每人 4 张母图、动作直接继承旧图，比纸娃娃（要先做合成器、锚点表、共用身体，还有生成器授权问题）省事得多。只有将来出现「全新角色、没有任何旧图可参考、参考重绘也出不稳」时再考虑；真做也是离线拼装，不做运行时叠图。
