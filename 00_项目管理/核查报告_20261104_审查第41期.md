## 逐批记录

### visual2：倒下粉碎（`collapse_fx.gd`）——你点名的两项

**反向验证（补做）**：对 `xiyou_collapse_fx`（55）逐处改坏实现，看测试是否咬住：

| 改动 | 结果 |
| --- | --- |
| 碎块边长 `/40` → `/50` | 咬住（count、rows 失败） |
| 碎块边长 `/40` → `/41` | **没咬住**（测试用的 5 种尺寸里，`/40` 与 `/41` 取整一致） |
| 每帧 `y -= sx` → `y += sx` | 咬住 |
| 行结束条件 `py > 0` → `py >= 0` | 咬住 |
| 不透明度速度 `op` 范围 +1 | 咬住（帧数变成 73） |
| 方向 Left 反成 Right | 咬住 |
| 镜像丢失 | 咬住 |
| 水平速度 `sx` 范围 [1,1.5) → [1.5,2) | **没咬住** |
| 碎块锚点 `offset(-frag/2, -frag)` → `(0,0)` | **没咬住** |

这三处没咬住的都是 P3（见 P3-1、P3-2）：规则对照原版源码我逐行核了，`setupColShatterPoint`／`updateCollapseShatterPoint` 的网格、取图框、起点、每帧位移、不透明度扣减、终止条件都一致（MOG_CollapseEffects.js 330～371 行）；只是测试没把这三个量钉住。

**实机对照**：没做，无头环境截不了战斗画面。我补的是源码级核对，下面两条是核对时发现的、探针量不到的差异。

- **P3-1（visual2）网格用的 `this.width／height` 在原版里含缩放，探针把它写死成位图尺寸。**原版 `setupColShatterPoint` 里 `this.height + this.width` 读的是 `Sprite_Enemy` 的 PIXI 宽高＝位图尺寸×|scale|。**非 SV 敌人在呼吸**（`YEP_X_AnimatedSVEnemies.updateBreathing`：scale.y＝1＋cos(c/s)×0.02，scale.x 振幅 0.001；visual1 自己量到 1814 个非 SV 敌人都呼吸），倒下那一帧 `scale.y` 在 0.98～1.02 之间，高度偏差最多 2%：边长 `floor((宽+高)/40)` 在边界上可能差 1，起点 `yi` 也会差几个像素。`collapse_probe.cjs` 的 `spriteOf` 把 `width`／`height` 覆盖成固定值，所以这个因素从未被量过；`collapse_fx.gd` 用的是区域尺寸（不含缩放）。影响是碎块多一圈／少一圈，纯画面，数据里没有 `Scale Sprite` 备注的敌人（我查了 Enemies.json，0 个），所以只剩呼吸这一项。建议：探针再加「呼吸相位 ±」的几例，或承认这一项为已知小差异。
- **P3-2（visual2）边缘碎块的锚点。**原版碎块用 `anchor=(0.5,1)`，PIXI 的锚点按 `texture.orig`（被裁剪后的取图框）算；位图边缘那一列／行，取图框被截成比 `frag_size` 小（MV `Sprite._refresh` 会把越界部分裁掉），锚点就落在更小的框上。`collapse_fx.gd` 对这些边缘块只缩了 `region_rect`，`offset` 仍按完整边长。偏移最多半个碎块（5 种测试尺寸里 `333×211` 这种边长不整除的会出现）。我没法在无头环境里证明 PIXI 这一步（探针里 Sprite 是桩），记为推断，需要实机或真 PIXI 才能定。上面反向验证里「锚点改 (0,0) 没咬住」说明测试也没碰这条。
- **P3-3（visual2，补充）**交付单里「渡鸦魔法反射支」「饿狼 0 伤」都没改、只记了判断，我没有反对；渡鸦那条结论（先不动 battle_logic，另派小任务量全）合理。
