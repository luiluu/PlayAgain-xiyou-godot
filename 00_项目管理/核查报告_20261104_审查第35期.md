### P2-1 钩子行判定放过真逻辑

位置：`07_开发环境/选测.py` `hook_modules`，`选测对照.json` `hookLines.glue`。

一行只要含一个非排除的 `X模块.成员`，就算钩子行，这行的其余内容不看。胶水白名单只管不含模块引用的行，但它也不看控制流。

用 `hook_modules` 在临时仓库实测（纯新增）：

| 新增内容 | 结果 |
| --- | --- |
| `var k = XFoo.f(1) * 2 + a.atk` | 判成钩子 |
| `hp = XFoo.f(hp) - 100` | 判成钩子 |
| `XFoo.go(); d.hp = 0` | 判成钩子 |
| `d.hp = 0; var s = "XFoo.x"`（字符串里的假引用） | 判成钩子 |
| `const K = XFoo.K * 100` | 判成钩子 |
| `XFoo.go()` 后接无条件 `return`／`return hp` | 判成钩子 |
| `return false` 改成 `XFoo.go()`＋`return true` | 判成钩子 |
| `return false` 删掉，换成 `XFoo.go()` | 判成钩子 |
| 只有 `return hp`、只有注释、换行续写的第二行 | 正确退回 |

历史上真发生过。扫主线最近 250 次合并，核心文件改动有 54 次（按文件计）被判成钩子，其中明显改逻辑的：

- `5bbccdcc` wukong-reach-air2，`battle_logic.gd` 闪避公式：`var base := 0.0 if XYomiJingliu.sure(u, skill) else _hit_formula(...)`、`return clampf(base + XToji.eva_bonus(u, skill, t), 0.0, 1.0)`。选测 204→154，掉了 xiyou_hit_warehouse、xiyou_shield、xiyou_state_effects、xiyou_state_effects_tp、xiyou_state_js、xiyou_formula_effects、xiyou_param_states、xiyou_boss_sequence 等。

- `80990e8d` bajie-growth1，`actor.gd`／`enemy.gd` 能力值链换层次，`XHubris.formula_param` 包到最外层。

上面的名单对比开了抽样（`--list` 默认口径）。**我只比了名单，没有把这些改动真跑一遍，所以不知道冒烟场景（rules 抽样、determinism 等）能兜住多少。** 每天一次的全量还在，所以这是「合并时晚发现」的风险，不是永远漏。

测试为什么没抓到：`HookLineTests` 的真逻辑例子（`var hp = 1 + 2`）不含模块引用；`HookHistoryTests` 只把 honghuang2 列为不该收窄，5bbccdcc 这类没列。交付单说的「真改了核心逻辑的仍全选」只在改动行不带模块引用时成立。

建议：
1. 钩子行只认独立语句：`XFoo.bar(...)`、`var x := XFoo.bar(...)`，赋值右边整个就是一次模块调用，不接算术、不接分号。
2. 胶水行只在紧跟这种 `var x` 时才放行（`if not x.is_empty(): return x`），裸 `return`、`return <变量>` 不算。
3. 只放行纯新增块：带删除行的块退回原组（包装链换层次、公式改写都走这条）。代价是 `XCat.param` 这类接力包装会退回全选，这正是该全选的。
4. `HookLineTests` 补上表各例，`HookHistoryTests` 把 5bbccdcc、f803fc1f 列成不该收窄。
